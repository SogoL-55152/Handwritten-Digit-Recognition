# miniprogram — 微信小程序

W1 交付：保留账号登录与受登录保护的业务首页，新增**免登录的本地画板原型**。
原型仅支持书写、清空、PNG 导出预览，不上传图片、不调用识别 API、不提供识别结果。

## 微信开发者工具运行

1. 导入 `miniprogram/`，AppID 可使用项目中的测试号 `touristappid`。
2. 使用支持 Canvas 2D 的基础库（项目配置为 `3.5.0`）。
3. 无需启动后端：从登录页点击「免登录体验 W1 本地画板」；也可以新增编译模式，启动页面填 `pages/drawing-prototype/drawing-prototype`，直接进入原型。
4. 如需测试原有登录，启动后端（默认 `http://localhost:8080`），在「详情 → 本地设置」勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」，使用演示账号 `admin / admin123`。
5. 登录成功进入业务首页后，也可以点击「打开 W1 本地画板」。

仅测试本地画板时，无需网络、后端服务或域名校验设置。登录相关真机联调时，需将 `app.js` 中的 `baseUrl` 改为电脑的局域网 IP，手机与电脑在同一网络，并放行后端端口。

## 页面与实现范围

| 路径 | 说明 |
|---|---|
| `pages/login/login` | 保留账号密码登录；提供免登录原型入口 |
| `pages/index/index` | 业务首页，仍要求完整登录缓存；提供原型入口与退出 |
| `pages/drawing-prototype/drawing-prototype` | 独立 W1 本地原型，无登录守卫、无网络请求 |
| `components/drawing-board/drawing-board` | Canvas 2D 画板、状态提示、清空与本地 PNG 预览 |

- 白底黑字，圆头圆角连续笔画；按下即填充实心圆，因此轻点也能产生像素。
- 根据 DPR 设置位图尺寸，触摸坐标仍使用画布内的逻辑像素；导出尺寸采用位图尺寸。
- 仅跟踪当前手指，结束 / `touchcancel` 后停止笔画，不将下一笔连接到上一笔。
- 未初始化时禁止操作；初始化失败显示重试入口；空白画布不能导出。
- 清空会重置墨迹、预览、末点和进行中的笔画。清空或继续书写后，旧导出成功 / 失败回调不能覆盖新状态；组件离开后也忽略迟到回调。
- `wx.canvasToTempFilePath` 使用 Canvas 节点和当前组件上下文，生成本地 PNG 临时路径供页面预览；不保存相册，不承诺重进页面仍保留。
- `utils/session.js` 统一启动、登录页和首页的会话判断：需要非空字符串 token 与用户对象同时存在；缺失 / 类型不符时同时清理两份缓存和全局状态，避免循环跳转。
- 本地会话完整性检查不是服务端身份验证。既有请求仍携带 Bearer token，业务 401 仍清理会话并返回登录页；原型开放不代表业务接口开放。
- 原有 `request()` / `upload()` 工具保留，画板和原型页不引用它们。识别、历史记录、上传业务不在 W1 本次交付范围。

## 自动化测试（无需安装依赖）

使用 Node.js 20 或更新版本，在此目录执行：

```sh
npm test
```

脚本是 `node --test`，使用内置 `node:test` 和 `node:assert/strict`，无第三方依赖、无需 `npm install`。测试目录及开发说明已从微信项目打包文件中排除。

也可使用现成的 Node 可执行文件直接运行（Git Bash 示例）：

```sh
"D:/Temp/hdr-tools/node-v20.15.0-win-x64/node.exe" --test \
  tests/drawing-board.test.js tests/session.test.js
```

测试加载**实际 Component / Page / App 与会话模块**，用 wx stub 和一个最小 Canvas 软件栅格 stub 验证行为，不只是语法检查。覆盖：

- 初始化失败 / 重试、未就绪保护、白底、DPR 1 / 2 / 3 / 2.625 与兼容回退。
- 单点实心像素、连续线段、抬手末点、分笔不相连、多指过滤、cancel。
- 清空的像素和状态重置、空白禁导出、PNG 节点 / 组件上下文 / 像素尺寸。
- 导出成功、失败、异常、缺失路径、重复点击、清空 / 绘制 / 离开后的过期回调与新旧导出交错。
- 半份缓存清理与无跳转循环、完整会话恢复、账号登录、无效登录响应、退出和既有 401 处理。

本次先在 Node v20.15.0 直接执行 `node --test`，45 项通过；旧 npm 缺文件的失败仅属于旧工具环境。随后在获准使用的 **Node v22.23.4 / npm 10.9.9** 上执行 `npm test`，**45 项全部通过**。测试仍是 stub 层验证，不等同微信真实 Canvas / 导出实现，**未执行开发者工具或真机验收，不声明真机通过**。

## 开发者工具人工验收清单（待执行）

以下方框刻意保持未勾选；请团队会前自行验收并记录实际结果，周四会议仅展示已完成成果。

### 入口与鉴权边界

- [ ] 清除 `hdr_token` 和 `hdr_user` 后，后端不启动，从登录页进入原型；也验证自定义编译模式直达原型，无登录跳转。
- [ ] 在原型绘制、清空、导出，检查 Network：不出现识别、上传或其他业务请求；页面仅显示本地 PNG 预览，无识别数字 / 概率。
- [ ] 正常登录后，业务首页显示用户，可进入原型并返回；退出仍回到登录页。
- [ ] 分别构造只有 token / 只有 user 的缓存，重新编译登录页与业务首页：两份缓存均被清理，停留登录页，不在 login / index 间循环。
- [ ] 清空会话后直接编译业务首页，应返回登录页；完整缓存可进入首页，过期 token 收到既有业务 401 时仍清理并回登录。

半份缓存可在开发者工具 Console 中设置后重新编译（两组分别执行）：

```js
// 只有 token
wx.setStorageSync('hdr_token', 'incomplete-test-token')
wx.removeStorageSync('hdr_user')

// 只有 user
wx.removeStorageSync('hdr_token')
wx.setStorageSync('hdr_user', { username: 'incomplete-test-user' })
```

### 书写与 PNG 预览

- [ ] 初始白底、空白导出按钮不可用。单击 / 轻点一次，能看见黑色实心点，导出的 PNG 也有该点。
- [ ] 连续写 `0`、`8` 和多笔数字，笔画跟随手指、圆头连续；抬手后下一笔不与上一笔连线。
- [ ] 画板区域触摸不会拖动整页；边缘书写、多指操作不导致跳线。真机触摸被系统手势打断（cancel）后，移动不续写，下一笔正常。
- [ ] 导出 PNG 的预览与画布一致：白色不透明背景，黑字完整，无裁切、偏移、拉伸；检查 DPR 1 / 2 / 3 机型或模拟器，图像像素尺寸为画布逻辑尺寸乘对应 DPR（取整）。
- [ ] 清空后画布全白、旧预览消失、空白导出禁用；清空中断当前笔画，后续书写无残留连线。
- [ ] 已有预览时继续书写，旧预览立即隐藏；再次导出得到新画面。
- [ ] 点击导出后立即清空 / 继续写，即使旧导出稍后成功或失败，也不能显示旧预览、旧错误或关闭新的导出状态。
- [ ] 模拟初始化失败时有错误提示和重试入口；导出失败时有提示、保留墨迹且能再次导出。自动化用例已覆盖这些注入故障，开发者工具仍需检查呈现。
- [ ] 离开原型再进入，画板为空，不复用过期临时路径；实际 iOS / Android 的触摸、DPR 与导出表现分别验收。
