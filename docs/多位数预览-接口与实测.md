# 多位数识别：接口与实测（含落库版）

> 2026-11-12。识别页新增「多位数（预览）」：画板写 1–4 个数字 → 垂直投影切分 → 逐字复用现有模型 → 返回整串。
> 两个端点并存：`/recognitions/multi` 是**落库版**（写历史、带幂等、进统计）；`/recognitions/multi-preview` 是**预览版**（不落库，仅用于对比与压测切分）。前端默认走落库版。

## 1. 怎么用

1. 打开 `/recognize`，左侧勾选「多位数（预览）」，选「最多 N 位」
2. 在画板写 1–4 个**间隔书写**的数字，或导入一张这样的照片（导入时会先做照片增强）
3. 点「识别多位数字」→ 右侧显示整串与逐位置信度

落库版会写入识别历史；图片导入会先做白底黑字 + 加粗的照片增强再切分。

## 2. 接口

```
POST /api/v2/workspaces/{workspaceId}/recognitions/multi-preview   (multipart)
  image       PNG/JPEG ≤5MiB
  maxDigits   1–4（默认 3）

200 {
  "preview": true,
  "text": "351",
  "accepted": false,
  "maxDigits": 3,
  "modelId": "mnist-cnn-w1", "modelVersion": "w4-task-8-a1",
  "digits": [{"digit":3,"confidence":1.0,"margin":0.99,"left":80,"right":230}, ...],
  "requestId": "..."
}
```

错误：

| 情况 | 状态 | category |
|---|---|---|
| 超过 maxDigits 位 | 422 | `DIGIT_LIMIT` |
| 空白图 | 400 | `BLANK_IMAGE` |
| maxDigits 非法 | 400 | `VALIDATION` |
| 图片格式/尺寸问题 | 400/413 | 与单字一致 |

模型服务侧是 `/internal/v2/predict/multi`（内部令牌），切分与逐字推理都在那里完成；`maxDigits` 走**查询参数**——multipart 的 part 数有上限（字段本身也占 part），不能再往表单里加字段。

## 3. 切分怎么做的

1. `foreground_ink` 得到墨迹图（与单字完全同一条预处理）；
2. 按列投影，连续空列达到画布宽度 2% 即视为一个分隔；
3. 每段按墨迹外框裁剪，长边缩放到 20px、居中贴到 28×28（与 `canvas_input` 同口径）——这一条是关键，口径不同会直接掉点；
4. 逐段跑现有 10 类模型，取 top-1 与 top-2 分差；
5. 每段 `confidence ≥ 0.90 且 margin ≥ 0.85` 才算接受，整串 `accepted = 全部位都接受`。

## 4. P0 实测（合成 1–4 位串，120 组/档）

数据来源：已下载的触屏笔迹集（20,074 个有效字形，253 位书写者），按画板规则渲染成多位串。

| 位数 | 整串正确率 | 逐位正确率 | 切分精确率 |
|---|---|---|---|
| 1 位 | **97.5%** | 97.5% | 100% |
| 2 位 | **91.7%** | 95.4% | 99.2% |
| 3 位 | **86.7%** | 95.6% | 100% |
| 4 位 | **85.8%** | 96.3% | 100% |

**结论：切分不是瓶颈（99–100%），瓶颈是逐位准确率。** 逐位 95.5% 是该数据域的精度；整串 ≈ 逐位^N，所以 3 位要 ≥90% 需要逐位 ≥96.5%。

## 5. 接口实测（真实后端 + 真实模型服务）

`.git/w2-local/multi-preview-smoke.py`，5 项全过：

```
PASS 1 三位数字返回整串与逐位        识别结果: 351 [(3, 1.0), (5, 1.0), (1, 0.63)]
PASS 2 标注为预览且带模型版本
PASS 3 超过位数上限被拒（422 DIGIT_LIMIT）
PASS 4 空白图被拒（400 BLANK_IMAGE）
PASS 5 maxDigits 非法被拒（400 VALIDATION）
```

（合成笔画写的 "357" 被读成 "351"，最后一位置信度 0.63 已被标红——这正是"低置信位要提示用户"的用法。）

## 6. 已知限制

- **只支持画板、间隔式书写**；连笔/黏连不承诺，图片导入暂不支持多位数；
- **不落库**：历史、统计、幂等都没有，重复提交会重复推理；
- 切分靠固定间隙阈值（画布宽度 2%），字写得太挤会少切而不是错切；
- 逐位阈值沿用单字的 0.90/0.85，未按多位数单独校准；
- 合成串来自触屏数据，**不能替代真实画板多位数测评**。

## 7. 要走到"可验收"还差什么

| 差距 | 做法 | 估算 |
|---|---|---|
| 逐位 95.5% → 96.5%+ | 用 2 万条触屏数据 + 自采画板样本微调 | 2 小时 |
| 真实多位数测评集 | 采 ≥100 串（5 人 × 20 串，约 30 分钟） | 0.5 小时 |
| 正式落库与统计 | V11 迁移（`result_text` 列）+ 统计适配 | 1.5–2 小时 |
| 小程序端 | 同接口接入 | 1–1.5 小时 |

## 8. 落库版：`POST /recognitions/multi`

### 8.1 接口

```
POST /api/v2/workspaces/{workspaceId}/recognitions/multi   (multipart)
  image            PNG/JPEG ≤5MiB
  source           WEB / MINIPROGRAM
  maxDigits        1–4（查询参数，默认 3）
  Idempotency-Key  UUID（请求头，必填）

200 {
  "recognitionId": "280",
  "requestId": "...",
  "text": "351",
  "accepted": false,
  "digits": [{"digit":3,"confidence":1.0,"margin":0.99,"left":80,"right":230}, ...],
  "modelId": ..., "modelVersion": ..., "preprocessVersion": ..., "processingMs": 90, "createdAt": "..."
}
```

行为：

- **写库**：一行 `t_recognition_v2`，`result_text` 存整串、`digits_json` 存逐位明细、`digit` 为 NULL；
- **幂等**：同一 `Idempotency-Key` + 同图重放返回**同一条记录**；同键换图返回 409 `IDEMPOTENCY_CONFLICT`；
- **失败也落库**：位数超限（422 `DIGIT_LIMIT`）、模型不可用等会把该行写成 `FAILED` 并记 `failure_code`；
- **统计口径**：`status` 只表示"跑没跑完"，新列 `accepted` 表示"结果能不能用"。统计的「返回结果」改为 `status='SUCCEEDED' AND accepted=1`，避免把"跑完但不确定"算成有效结果；
- **最近识别**：直接显示整串（`resultText`），不再显示单个数字。

### 8.2 V11 迁移

```sql
ALTER TABLE t_recognition_v2
  ADD COLUMN result_text VARCHAR(8) DEFAULT NULL AFTER digit,
  ADD COLUMN digits_json JSON DEFAULT NULL AFTER result_text,
  ADD COLUMN accepted TINYINT(1) NOT NULL DEFAULT 0 AFTER digits_json;

UPDATE t_recognition_v2 SET accepted = 1 WHERE status = 'SUCCEEDED';   -- 历史单字回填
```

### 8.5 图片导入（2026-11-12 补）

多位数现在支持导入图片，链路与画板一致，只是在切分前多一步照片增强：

`
POST /workspaces/{wid}/recognitions/multi?maxDigits=3&enhance=true
`

- enhance=true 时，模型服务先做光照归一化 + Otsu + 加粗，再投影切分；
- 前端在图片模式自动带上 enhance=true，画板模式不带；
- 图片模式的「多位数识别」开关与画板共用，选到图片即可提交。

实测（合成带阴影的三位数照片，760×340 JPEG）：

`
PASS 1 图片多位数返回整串             增强后: 200 351 [(3,1.0),(5,1.0),(1,0.84)]
PASS 2 逐位结果与整串一致
PASS 3 落到识别历史（带记录号）
PASS 4 画板多位数不受影响
`

（7 被读成 1 仍是模型的照片域短板，与单字照片命中率一致。）
