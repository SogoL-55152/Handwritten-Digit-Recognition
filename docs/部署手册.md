## 二、方式一：Docker 一键部署（推荐）

### 2.1 前置条件

| 要求 | 检查命令 |
|---|---|
| Docker Desktop / Docker Engine | `docker --version` |
| Docker Compose 插件 | `docker compose version` |
| 端口 8088 空闲 | `netstat -ano \| findstr :8088` |

### 2.2 步骤

```bash
# 1. 切到部署分支
git checkout deploy-work-backup

# 2. 一条命令启动
./start.sh          # Windows 双击 start.bat
```

脚本自动完成：

1. 生成 `.env`（随机数据库密码、JWT 密钥、内部 token、管理员密码）
2. 下载基线权重并校验 sha256
3. `docker compose up -d --build`（6 个服务）
4. 等待健康检查通过
5. 打印访问地址与管理员账号密码
6. 自动打开浏览器

### 2.3 验证

```bash
docker compose ps          # 6 个服务 healthy
curl http://127.0.0.1:8088
```

### 2.4 停止 / 重置

```bash
./stop.sh      # 停止，数据保留
./reset.sh     # 清空数据重来（会二次确认）
```

## 三、方式二：本机模式部署（无 Docker）

### 3.1 前置条件

| 依赖 | 版本 | 检查 |
|---|---|---|
| JDK | 17 | `java -version` |
| Maven | 3.9 | `mvn -v` |
| Node | 20–22 | `node -v` |
| Python | 3.11（含 torch 2.5 CPU） | `python --version` |
| MySQL | 8.0 | `mysql --version` |
| Redis | 7 | `redis-server --version` |

### 3.2 步骤

```powershell
# 1. 切到部署分支
git checkout deploy-work-backup

# 2. 准备配置
Copy-Item scripts\.env.example scripts\.env
#    修改其中的 JAVA_HOME / PYTHON / NODE / MYSQL_* / REDIS_* 路径

# 3. 建库与账号（MySQL 已启动）
mysql -h127.0.0.1 -P13316 -uroot -p -e "
CREATE DATABASE IF NOT EXISTS hdr_w2 CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'hdr'@'%' IDENTIFIED BY 'HdrLocal#2026';
GRANT ALL PRIVILEGES ON hdr_w2.* TO 'hdr'@'%';
FLUSH PRIVILEGES;"

# 4. 准备依赖
powershell -ExecutionPolicy Bypass -File scripts\fetch-weights.ps1   # 权重
python scripts\fetch-mnist.py                                         # 训练需要
cd backend; mvn -o -B package -DskipTests; cd ..                      # 后端 jar
cd frontend; npm ci; cd ..                                            # 前端依赖

# 5. 配置引导管理员（写入 scripts\.env）
#    HDR_BOOTSTRAP_ADMIN_USERNAME=admin
#    HDR_BOOTSTRAP_ADMIN_PASSWORD=你的密码

# 6. 启动
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1
```

### 3.3 停止

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1
```

## 四、关键环境变量

| 变量 | 说明 |
|---|---|
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | 数据库连接 |
| `V2_JWT_SECRET` | 至少 32 字节，登录签名 |
| `MODEL_INTERNAL_TOKEN` | 后端 ↔ 模型服务，**三处必须一致** |
| `MODEL_REGISTRY_PATH` / `WEIGHTS_DIR` | 模型注册表与权重目录 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_URL` | 三个都要给，只给 URL 会导致日志接口空返回 |
| `HDR_BOOTSTRAP_ADMIN_*` | 空库时创建的 SUPER_ADMIN |
| `HDR_IMPORT_ROOT` | 允许导入的根目录，多个用 `;` 分隔（如 `D:\;C:\`） |
| `TRAINING_DATA_DIR` | MNIST 原始 IDX 目录 |
| `TRAINING_CALLBACK_URL` | worker 回调后端地址 |

完整模板见 `scripts/.env.example`。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 8088/5173 打不开 | 服务未起 / 端口被占 | `docker compose ps` 或 `start-all.ps1` 重跑 |
| 后端起来但日志接口空 | 漏了 `REDIS_HOST/REDIS_PORT` | 补上，只给 `REDIS_URL` 不够 |
| 识别 400「图片未通过模型服务校验」 | 权重与 registry 不一致 | 重新 `fetch-weights`，或比对 DB 生效版本 sha256 |
| 登录成功但默认空间为空 | 空库引导管理员没有个人空间 | 使用包含修复的版本（`b2e8107` 之后） |
| 训练报「缺少 MNIST IDX」 | 没准备训练数据 | 运行 `scripts/fetch-mnist.py` |
| 导入 C 盘目录被拒 | `HDR_IMPORT_ROOT` 没包含 `C:\` | 设为 `D:\;C:\` |
| 训练参数 400「字段必须与约定一致」 | 后端与模型服务参数白名单不同步 | 用同一版本代码 |

## 八、注意事项

1. 管理员默认密码只显示一次，也会写进 `.env`，部署后请立即修改
2. `scripts/.env` 含密钥，**不要提交到 git**
3. Docker 数据在 volume 里；本机模式数据在仓库的 `collected-samples/`、`training-data/`、`model-service/weights/`
4. 迁移由 Flyway 自动执行，**不要手工改历史迁移文件**
5. 当前仓库 `develop` 已回退到部署前版本；部署前务必切到 `deploy-work-backup`
