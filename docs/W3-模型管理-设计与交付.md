# W3 模型管理：设计与交付

> 2026-11-07。Sprint 目标：**模型管理：多模型、单一活跃、一键切换**（里程碑：模型管理闭环）。
> 本页记录架构决定、接口契约、验收证据与仍然欠缺的部分。

## 1. 改造前的问题

W2 结束时"换模型"要改代码并重新打包客户端，原因是三个硬编码：

| 位置 | 改造前 | 问题 |
|---|---|---|
| `services/inference_manifest.py` | 单一不可变 `BASELINE`（版本、sha256、字节数） | 只能有一个模型 |
| `backend ModelClient` | `SHA / VERSION / PREPROCESS` 常量 | 换模型要改代码重新打包 |
| 网页与小程序 | 结果里的 `modelVersion` 白名单写死 | 换模型连客户端都要重发 |

## 2. 设计：两个权威，各自守一条边界

- **数据库是"哪个模型生效"的唯一权威**：`t_v2_model` 每行带 `sha256 / size_bytes / artifact / status`，由 `active_marker` 生成列 + 唯一索引保证**同一时刻只有一个 PUBLIC 模型为 ACTIVE**。
- **模型服务的 `registry.json` 是"哪些文件可信"的唯一权威**：每个条目声明 `artifact`（相对 `WEIGHTS_DIR` 的路径）、`sha256`、`sizeBytes`；服务在重载与首次加载时做**路径逃逸检查 + 大小 + 摘要**校验，未通过的条目不进入可推理集合（fail closed）。

注册与激活必须两边一致：

- 注册只接受 `externalId + version`，摘要、大小、artifact、预处理版本**一律取自注册表**，客户端不能自报。
- 激活前先让模型服务重载注册表，要求同版本条目 `verified=true` 且**摘要与数据库行一致**，否则 409 拒绝。

## 3. 接口契约

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/v2/admin/models` | SUPER_ADMIN | 全部 PUBLIC 模型行 + 注册表校验状态（`verified`、`registryReason`） |
| `POST /api/v2/admin/models/register` | SUPER_ADMIN | 从注册表登记新模型，落库为 `INACTIVE` |
| `POST /api/v2/admin/models/{id}/activate` | SUPER_ADMIN | 切换生效模型（唯一活跃） |
| `POST /api/v2/admin/models/{id}/disable` | SUPER_ADMIN | 停用；活跃模型不能停用（409） |
| `DELETE /api/v2/admin/models/{id}` | SUPER_ADMIN | 删除；有识别记录引用时 409 `MODEL_IN_USE` |
| `POST /api/v2/admin/models/registry/reload` | SUPER_ADMIN | 让模型服务重读 `registry.json` |
| `GET /internal/v2/models` | 内部令牌 | 注册表视图（含 artifact、摘要、校验结果） |
| `POST /internal/v2/models/reload` | 内部令牌 | 重新读取注册表 |
| `POST /internal/v2/predict` | 内部令牌 | 表单里的 `modelId/modelVersion/preprocessVersion` 必须在注册表中且校验通过，否则 400 `MODEL_NOT_ALLOWED` |

`/internal/v2/ready` 的语义改为：**服务存活 + 注册表里至少有一个通过校验的模型**，返回 `{status, verifiedModels, models, registry}`，不再钉单一 sha256。

识别路径：`RecognitionService` 取当前活跃模型 → 记入 `t_recognition_v2.model_version` → 调用模型服务。**历史记录保留当时的版本**，切换不回写历史。

客户端（网页 / 小程序）不再钉版本字符串，只校验形状（`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`）；允许与否由服务端注册表与数据库裁决。这是有意的取舍：W2 的白名单是为了防契约漂移，现在漂移由服务端强制。

## 4. 数据库变更（V6）

```text
t_v2_model + sha256 CHAR(64), size_bytes BIGINT, artifact VARCHAR(128)
           + active_marker  GENERATED ... STORED,uq_v2_model_single_active(scope, active_marker)
           + public_key     GENERATED ... STORED,uq_v2_model_public_version(public_key)
```

`active_marker` 只在 `scope='PUBLIC' AND status='ACTIVE'` 时为 1，NULL 不冲突，因此**数据库层面就不可能有两个活跃公共模型**，不依赖应用层自觉。已应用的 V2/V4/V5 没有任何修改（Flyway 校验和不变）。

## 5. 验收证据

真实 MySQL + 真实 Java + 真实模型服务（registry.json 内两个已校验模型），端到端脚本 18 项全部通过：

| 组 | 检查 |
|---|---|
| 1 注册表 | 热加载后列出两个已校验模型；数据库初始只有一个模型行；注册表里的未登记模型可见但未落库 |
| 2 注册 | 新模型落库为 INACTIVE；artifact 与 sha256 取自注册表而不是请求 |
| 3 切换 | 切换前识别用旧模型；激活返回新模型；**下一次识别立刻使用新模型且数字正确**；恰有一个 ACTIVE；旧模型保留为 INACTIVE |
| 4 切回 | 切回后识别立刻回到旧版本 |
| 5 权限 | 普通用户读取/激活均 403；活跃模型停用 409 |
| 6 边界 | 非活跃模型可停用；历史记录保留自己的模型版本 |

## 6. 仍然欠缺的部分（不作已交付）

- **自采画板/相册数据集 ≥1000 条（M5）没有完成**：这是必须由人采集的数据，本轮只准备了入口——采集清单模板 `docs/templates/recognition-samples.example.json` 与离线诊断脚本 `model-service/evaluate_samples.py`（`--origin actual-user-board|actual-user-album`、`consent:true` 必须由提供者填写）。**没有样本就不能宣称真实画板/相册准确率**。
- 模型文件仍由管理员放进 `weights/` 并写入 `registry.json`；**没有上传接口**（W3 范围就是不接受公网上传权重）。
- 切换没有审计表，只有数据库现状与识别记录里的历史版本可追溯。
- 管理页只在开发模式下可见（SUPER_ADMIN），尚未做真机/浏览器验收记录。
- 训练任务、队列、曲线属于 W4，本轮未做。

## 7. 复现与运行

```text
# 1) 权重与注册表（本机，weights/ 被 git 忽略，摘要钉在 registry.json 与数据库行）
#    registry.json 至少包含一个条目：modelId / version / preprocessVersion / artifact / sha256 / sizeBytes
# 2) 起服务
python -I scripts/local-demo.py model   --env-file <私有env.json> --python <python.exe> --allow-development-registration
python -I scripts/local-demo.py backend --env-file <私有env.json> --java <java.exe>     --allow-development-registration
python -I scripts/local-demo.py check   --env-file <私有env.json> --allow-development-registration
# 3) 管理（SUPER_ADMIN 令牌）
POST /api/v2/admin/models/registry/reload
POST /api/v2/admin/models/register        {"externalId":"mnist-cnn-w1","version":"<version>"}
POST /api/v2/admin/models/<id>/activate
```

`local-demo.py check` 现在校验的是"注册表里至少有一个通过校验的模型"，不再比对单一 sha256。
