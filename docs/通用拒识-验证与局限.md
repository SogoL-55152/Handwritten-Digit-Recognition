# 通用拒识：本地验证与已知局限

2026-11-04，面向项目成员。用户选择先做通用拒识，暂未提供实际9/乱画输入。本轮本地实现与验证，未提交、未推送、未发布。

## 当前结论

**已增加“无法可靠识别，请清空后重新书写”的拒识分支，并验证Python→Java→网页的真实422链路。并未解决任意非数字识别，也不能确认用户的9→7已修复。**

## 实现

- 不重训、不替换W1可信checkpoint、不改预处理像素；保持模型/预处理版本与历史记录一致。
- 新增独立接受策略 `selective-digit-v1`：宽幅且包围盒填充率≥90%的明显实心块、≥4个显著分离区域可拒绝；保留细长1/带环8/9结构，不以孔洞/单笔本身判无效。
- 最高softmax≥0.90、与第二类分差≥0.85才接受。参数在实验前固定，不是经过真实手写校准的数字有效性概率。配置必须有限合法，错误配置不静默关闭策略。
- Python返回422/code422/category `UNRECOGNIZED_INPUT`，没有digit/confidence；Java只接受符合错误合同的422并使用固定中文提示，其他未知或畸形响应仍502。
- 模型输出异常仍是基础设施故障，不伪装成用户拒识。拒识释放并发槽，不自动重发POST。
- 拒识请求写为FAILED，digit/confidence保持NULL，不增加成功次数；本人total/failed包括已写入拒识尝试。未改数据库schema，也不将拒识当正确识别。
- 两端保留有效会话，显示清空后重写提示；清空/新笔画/切换/注销后迟到响应不污染新结果。

### 真实联调发现与修复

模拟HTTP测试最初通过，但实际422被误报为502。新增本机真实HTTP服务用例复现：`SimpleClientHttpRequestFactory`背后的HttpURLConnection在先读正文时未初始化错误流，触发IOException。将读取顺序改为先状态后正文，保持响应体65KiB有界、白名单状态和超时预算。真实HTTP回归及浏览器链路重跑通过，没有仅靠mock宣称成功。

浏览器只使用本地测试主体配置，HTTP内部凭据/注册码不写到证据。测试在专用本机数据库执行，没有公网部署、微信UI操作或自动修改工具安全设置。结束后Java/Python/Vite/MySQL均已关闭。

## 固定策略的离线评估

完整报告使用本地官方MNIST测试IDX的10,000张原始28×28输入，不是手机/浏览器画板准确率。测试集仅作固定策略后的回归，没有用它搜索阈值；已有训练集也未被当作未见校准集。

| 指标 | 结果 |
|---|---|
| 无拒识基线正确数 | 9,910/10,000（99.10%） |
| 接受样本数/覆盖率 | 9,722/10,000（97.22%） |
| 合法数字被拒绝 | 278/10,000（2.78%） |
| 接受样本正确数 | 9,707/9,722（99.8457%） |
| 接受且正确/所有输入 | 9,707/10,000（97.07%） |
| 接受后仍错误 | 15张 |

**不能只拿99.8457%宣称整体准确率提高**：它排除了被拒绝样本，覆盖率及全部输入正确数必须同时报告。MNIST类9中有1,009张，954张被接受且正确，55张被拒绝；这不能证明用户那张9解决。

### 合成样例（不是独立真实手写评测）

- 开发组：20/20合成数字接受且正确；12/12非数字拒绝。
- 留出组：18/20数字接受且正确，2张预期6被拒绝；12张非数字中10张拒绝、**2张乱画仍被接受**。
- 两张漏拒案例：`holdout-random_scribble-0`→2（分数约.96394，分差.92993）；`holdout-random_scribble-2`→8（约.93638，分差.88761）。两者均高于阈值，直接证明阈值不等于非数字检测。
- 单笔直线探针单列：每组4张中3张被接受，包含竖线/斜线像1、横线像7。单线与数字写法可能歧义，未把这些排除信息隐藏。
- 开发/留出组使用不同固定种子与几何变体，但共享合成模板；不能称来自独立书写者的数据，也不能计算真实画板准确率。
