# 参数可视化（新）：四步向导实现说明

> 2026-11-18。按《参数可视化界面设计方案》实现的**并行新页面**，不改动已有页面（`/visual`、`/training`）。
> 目的：和旧页面并排对比效果。

## 入口

工作台左侧导航 →「**参数可视化**」（`/wizard`）。

```
① 数据集 ─ ② 参数 ─ ③ 监控 ─ ④ 评估
```

## 各步骤做了什么

### ① 数据集

- 选数据集 → 选版本（复用 `/datasets`、`/datasets/{id}/versions` 接口）；
- 训练/验证/测试**比例条**（真实统计，来自版本 stats）；
- 样本缩略图（复用版本样本图片接口，只读展示）；
- 不选版本时按内置 MNIST 60,000 条估算。

### ② 参数（本方案的核心）

**左栏：schema 驱动表单**

`frontend/src/wizard/schema.js` 定义四个分组（数据 / 结构 / 超参 / 运行），前端按
`group → items → widget` 渲染。支持 `dependsOn`：选 SGD 才出现动量，开早停才出现 patience。

| 控件 | 参数 |
|---|---|
| Select | 结构预设、优化器、设备、数据版本 |
| 对数滑块 + 输入框 | 学习率（1e-5 ~ 1e-1） |
| 分段按钮 | batch 16/32/64/128/256 |
| 滑块 | epochs、patience |
| 开关 | 数据增强、早停、混合精度、AMP |

**层编辑器**：卷积层可改 filters / kernel / padding，全连接层可改 units，右侧结构图与参数量实时重算。

**右栏：实时估算（纯前端，输入即反馈）**

| 面板 | 内容 | 算法 |
|---|---|---|
| 结构图 | 每层输出形状 + 该层参数量 | `inferShapes` 逐层推演 |
| 参数量 | 总参数（默认 CNN-2Conv = **421,642**，与线上模型一致） | conv: k²·Cin·Cout+Cout；linear: Cin·Cout+Cout |
| 显存 | 激活 + 参数（含优化器状态），AMP ×0.6 | `estimateMemory` |
| 耗时 | 单步 / 单 epoch / 总耗时 | 以 421k 参数、batch 64 为基准线性插值（CPU 12ms、GPU 1.2ms） |
| 校验 | ✓ / ⚠ / ✗ 三态，警告给可执行建议 | `validateConfig` |
| 配置摘要 | 归一化后的 JSON + `config_hash`（sha256 前 12 位） | `normalizeConfig` + `configHash` |

校验规则（与方案对齐）：

- ✗ 形状推演失败（如 24×24 上做 25×25 卷积）→ 阻止进入下一步；
- ⚠ batch 显存超预算 → 给出"建议 batch ≤ N 或开 AMP"；
- ⚠ Adam 学习率超出 5e-4~1e-3 常用区、SGD 学习率 < 1e-3；
- ⚠ epochs > 20 且未开早停；
- ⚠ 设备为 CPU 时提示耗时约为 GPU 的 10 倍。

### ③ 监控

复用真实训练任务（`/admin/training/tasks`）：逐轮曲线、参数卡片、逐轮明细表（损失/三域准确率/耗时）。
这是**历史回放**，不是实时 WS 推送——方案里的"实时样例墙"需要模型服务在训练中回传样例，暂未实现。

### ④ 评估

同一任务的 MNIST / 画板模拟 / 照片模拟三域准确率 + 每类准确率 + 混淆矩阵（复用 `TrainingMatrix`）。

## 改版：训练并入向导 + 监控细化（2026-11-18）

### 1. 发起训练移到向导

- 第②步底部新增「开始训练」：按 schema 里的 epochs/samples/batchSize/learningRate/seed/photoRatio/微调起点 + 第①步的数据集与版本提交任务；
- 提交成功后自动跳到第③步并绑定新任务；
- /training 只保留任务列表、曲线回放、详情与评估，顶部提供「去参数可视化发起训练」；
- **整页仅管理员**：路由 meta.superAdmin，普通用户看不到导航项。

注意：网络结构 / 优化器 / AMP / 早停仍是展示与估算（训练管线固定 CNN-2Conv + Adam），界面上不再暗示它们会生效。

### 2. 监控指标

第一档（已做）：

| 指标 | 说明 |
|---|---|
| 训练集准确率 | 每轮取最多 1000 个训练样本评估 |
| 学习率 lr | 每轮记录 optimizer 的当前 lr |
| 吞吐 tps | 样本数 ÷ 轮耗时 |
| 梯度范数 | 每轮最后一个 batch 的 L2 范数 |
| 最优轮次 | 按画板模拟准确率取最高轮，详情表打 ★ |
| 数据构成 | 已训练样本数、额外样本数 |

第二档（已做）：

| 指标 | 说明 |
|---|---|
| step 级采样 | 每约 640 个样本记一条 loss/lr（最多 500 点），存进 metrics.stepSeries |
| 日志流 | worker 的 stdout 同时写入 Redis 	raining:log:<id>（2000 行环形），页面「日志」按钮展开 |

接口：GET /api/v2/admin/training/tasks/{id}/logs → { lines: [...] }。

实测任务 #24：指标键含 gradNorm/lr/tps/trainAcc，estEpoch=2，日志 2 行已入 Redis。
## P0 + 部分 P1：参数界面“详细化”（2026-11-19）

### P0

| 项 | 说明 |
|---|---|
| 只读标注 | 结构预设、优化器、学习率调度、AMP 标「仅估算」，明确它们不参与真实训练 |
| 分组折叠摘要 | 四个分组可折叠，收起时显示当前取值摘要（如 Adam · lr 1.0e-3 · 10000）|
| 分层参数表 | 每层参数量 + 占比条形图，能看出全连接占大头 |
| 显存四项拆分 | 权重 / 梯度 / 优化器状态 / 激活分开展示 |
| 耗时校准 | 用历史任务每轮耗时反推 ms/step 中位数；有历史时显示“按历史 N 个 epoch 校准” |
| 日志过滤 | 训练日志支持级别（INFO/WARN/ERROR）与关键字过滤，显示命中行数 |

### P1（已完成部分）

| 项 | 说明 |
|---|---|
| 参数模板 | 快速上手 / 高精度 / 手机笔迹鲁棒三套，一键套用（同时重置结构预设） |
| 学习率预览 | 选调度器后画 lr 曲线（SVG，不引入新依赖） |
| 过拟合诊断 | 监控页：验证指标变差而训练损失下降时给出黄色提示 |

### 还没做（P1 剩余）

- 草稿自动保存/恢复（localStorage）
- 配置 diff（与历史任务逐项对比）
- 增广预览（旋转/平移/缩放后的样本缩略图）
- 每轮混淆矩阵（需要模型服务每轮存 10×10）
