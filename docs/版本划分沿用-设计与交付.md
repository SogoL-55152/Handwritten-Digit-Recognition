# 版本合并时的「保留旧划分」

> 对应交接文档 P1-12：「数据集版本合并的『保留旧划分』选项——现在每次重建都重新随机划分」
> 完成日期：2026-11-25

---

## 1. 问题确认（先验证再动手）

划分其实是**确定性哈希**，不是每次随机：

```java
String seed = rule.equals("RANDOM") ? sampleId + ":" + datasetId : writer + ":" + datasetId;
int bucket = Math.floorMod(seed.hashCode(), 100);
if (bucket < test) return "TEST";
if (bucket < test + val) return "VAL";
return "TRAIN";
```

所以同一数据集、同一比例、同一批样本，重建结果完全一样。**但**只要动了下面任何一项，隶属关系就会洗牌：

| 动作 | 后果 |
|---|---|
| 改 `valPercent` / `testPercent` | 分桶阈值变了，原来的测试集样本会滑进训练集 |
| `WRITER` ↔ `RANDOM` 切换 | 种子从书写者换成样本 id，整批重排 |
| 合并别的数据集的样本 | 种子里的 `datasetId` 是**新数据集**的，老样本也按新种子重算 |
| 新导入一批样本 | 新样本进来本身不影响老样本，比例不变时老样本稳定 |

实测证据（数据集 #6，1200 样本，v1 为 RANDOM 15/15）：仅把比例改成 30/30 重建，
**599 / 1200 条样本的划分发生了变化** —— 测试集一半换了人，跨版本指标自然不可比。

## 2. 现在的做法

`POST /datasets/{id}/versions` 的请求体新增可选字段：

```json
{ "version": "v5", "splitRule": "RANDOM", "valPercent": 30, "testPercent": 30,
  "preserveSplitFrom": 7 }
```

- 非空时，**来源版本里已存在的样本沿用原来的 `split`**；只有这次新增的样本按百分比重新分配。
- 来源版本必须是**同一数据集**且状态 `READY`，否则 `400 SPLIT_SOURCE_INVALID`——
  拿别的数据集的划分来套是没有意义的（两个集合根本不是同一批样本）。
- 新版本行记录 `split_source_id`（迁移 **V23**），前端版本条显示「沿用 #7」，接口 `Version.splitSourceId` 也带出来。
- 不传 = 现在的行为（按比例重新划分），完全向后兼容。

前端在「生成版本」表单加了一个 **划分来源** 下拉（默认「重新划分」），选中后显示一条橙色提示说明影响范围。
下拉只列同一数据集里 `READY` 的版本，并排除正在新建的那个名字。

## 3. 验证

| 项 | 结果 |
|---|---|
| 后端单测 | 新增 `DatasetSplitTest` **6 项**：沿用优先、无沿用则回落哈希、RANDOM 确定性、WRITER 不拆人、比例大致符合、比例清零时全 TRAIN |
| 前端单测 | `datasets.test.js` 新增 **2 项**：`preserveSplitFrom` 只在正整数时提交；来源列表排除未就绪版本与当前版本名。前端 **312 项**全通过 |
| 回归 | `mvn -Pmysql-it verify`：**192 单测 + 26 集成** BUILD SUCCESS；`npm run build` 通过 |
| 迁移 | 启动后 `flyway_schema_history` 最新版本 = **23** |

端到端实测（`verify_p112.py`，真实接口 + 真实数据库）：

| 场景 | 结果 |
|---|---|
| 沿用 v1 的划分，但把比例改成 30/30 重建 | 1200 样本，**与 v1 划分相同 1200 条（100%）**，`splitSourceId=6` |
| 不沿用、同样 30/30 重建 | 1200 样本，**与 v1 不同 599 条**，`splitSourceId=null` |
| 用别的数据集（#5）的版本当来源 | `400 SPLIT_SOURCE_INVALID` |

两条对照放在一起才能说明问题：**改比例确实会洗牌（599 条），而"沿用"能把它完全钉住（0 条变化）**。

## 4. 已知局限

1. **只沿用已有样本**：新增样本仍按当前比例分配，因此沿用后的 `TRAIN/VAL/TEST` 实际比例会与表单里填的百分比不一致
   （界面提示里已写明）。想要"新增样本也进原来的测试集"是不合理的，它们本来就不在旧测试集里。
2. **不校验旧划分的完整性**：如果来源版本本身只有 TRAIN（比如当时样本 ≤3 触发了比例清零），
   沿用后会得到同样"没有测试集"的版本，只保留"至少有 1 条 TRAIN"的兜底。
3. **划分来源不能跨数据集**（有意限制）；跨数据集合并请先归入同一数据集再建版本。
4. **不记录"哪些样本沿用了"**：只记录来源版本 id。要逐条核对需对比两个版本的 `t_v2_dataset_sample`。
5. **已经有多个版本时下拉会变长**：前端未做搜索/分页（当前数据集版本数是个位数）。
