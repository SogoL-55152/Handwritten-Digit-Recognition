# 识别详情与原图

> 2026-11-12。统计页「我的最近识别」每行加了「查看」，点开可看**这张图**和**当时的识别结果**。
> 之前识别只存摘要（`image_digest`），没有原图，所以这次先把原图落盘，再做查看。

## 1. 交互

`/statistics` → 「我的最近识别」→ 每行「操作」列有「查看」：

- 弹出卡片：左上是原图，下面是结果、状态、是否可用、置信度、耗时、失败分类、模型、预处理、来源、时间、请求 ID；
- 旧记录（V14 之前）没有图，弹窗显示「该记录没有保存图片」；
- 平台范围（别人的记录）按钮禁用——只允许看自己的。

## 2. 接口

```
GET /api/v2/workspaces/{wid}/recognitions/{id}/detail
  200 { recognitionId, requestId, status, digit, resultText, accepted, confidence, processingMs,
        modelId, modelVersion, preprocessVersion, source, failureCode, createdAt, hasImage }

GET /api/v2/workspaces/{wid}/recognitions/{id}/image
  200 图片字节（Content-Type: image/png | image/jpeg, Cache-Control: private）
  404 该记录没有保存图片 / 记录不存在
```

两个接口都要求：工作空间成员 + **记录创建者本人**（`creator_id = 当前用户`），不提供任何列表接口。

## 3. 存储

| 项 | 做法 |
|---|---|
| 目录 | `hdr.recognition.dir`（环境变量 `HDR_RECOGNITION_DIR`），默认仓库根下 `recognition-images/` |
| 路径 | `<root>/<workspaceId>/<yyyyMM>/<sha256>.png`，写入前校验不逃逸出根目录 |
| 去重 | 按图片摘要：同一张图多次识别只存一份 |
| 时机 | **识别前**就写盘（失败记录也能看原图，便于排查） |
| 数据库 | `t_recognition_v2.image_path` + `image_type`（V14） |
| 隐私 | 只有本人能读；`.gitignore` 已忽略目录；暂无自动清理（见限制） |

## 4. 实测（真实后端 + 真实 MySQL）

`.git/w2-local/recognition-detail-smoke.py`，6 项全过：

```
PASS 1 新单字记录详情可读且标记有图
PASS 2 原图可下载且是 PNG
PASS 3 多位数详情返回整串与有图标记
PASS 4 多位数原图可下载
PASS 5 旧记录详情标记无图、取图返回 404
PASS 6 不存在的记录返回 404
```

## 5. 已知限制

- **没有保留策略**：识别图会一直累积（每张约 20–40 KB，1000 次约 30 MB）。按时间清理/按需删除留到 W8。
- 旧记录无法补图（当时没存）。
- 平台管理员看不到别人的原图（有意为之）；如果验收需要"抽查他人记录"，要先加审计与授权。
- 前端图片用 blob URL，关闭弹窗时释放；同一记录重复打开会重新拉取。
