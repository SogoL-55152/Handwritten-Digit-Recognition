## 1. 分层与调用关系

```
前端 / 小程序
   │  HTTPS + JWT
   ▼
Controller（鉴权、参数校验、Result 包装）
   │
Service（业务规则、事务边界）
   ├── JdbcTemplate → MySQL
   ├── CollectedSampleService → 文件系统（内容寻址）
   ├── ModelClient → 模型服务 /internal/v2/*（内部令牌）
   └── TrainingService → ModelClient.enqueueTraining → Celery 队列

Celery worker ──训练──▶ 回调 POST /internal/v2/training/{id}/state
                     └─ 日志写 Redis training:log:<id>
```

## 2. 鉴权与上下文

| 项 | 说明 |
|---|---|
| 登录 | `POST /api/v2/auth/login` 返回 JWT；后续 `Authorization: Bearer <token>` |
| 会话 | JWT 中的 `sessionId` 对应 `t_auth_session`，登出/过期后令牌立即失效 |
| 空间上下文 | 路径里的 `workspaceId` 必须与调用者成员关系匹配（`spaces.requireMember`） |
| 平台上下文 | `/admin/**` 与 `/platform/**` 需要 `platform_role = SUPER_ADMIN`（`requireOperator`） |
| 内部调用 | worker 回调带 `X-HDR-Internal-Token`，与 `hdr.internal.token` 比对 |
| 识别原图 | 只有创建者本人可读（`/recognitions/{id}/image` 校验 creator） |

## 4. 通用约定

| 项 | 约定 |
|---|---|
| 响应包装 | `{ "code": 0, "message": "ok", "data": ... }`；非 0 为错误 |
| 错误结构 | 业务错误 `data.category` 给出机器可读码；同时用 HTTP 状态码表达类别 |
| 时间格式 | ISO-8601（`2026-11-19T12:00:00Z`） |
| 分页 | `page`（1 起）、`size`（服务端上限 60）；返回 `items/total` |
| 幂等 | 识别接口用 `requestId`（客户端生成 UUID）；重复请求返回同一结果 |
| 上传 | 单图 ≤ 5MB；导入 zip ≤ 500MB；`multipart/form-data` |
| 超时 | 普通接口 20s；导入/训练提交 600s；裁字 30min（服务端） |
| SSE | `POST /admin/training/tasks/events/ticket` 换票，再 `GET /events?ticket=` 订阅 |

## 6. 训练任务接口细节

### 6.1 创建任务

`POST /api/v2/admin/training/tasks?datasetId={id}`，body：

```json
{
  "epochs": 3, "samples": 10000, "batchSize": 64, "learningRate": 0.001,
  "seed": 42, "photoRatio": 0.5, "useEmnist": false,
  "initFrom": "w4-task-8-a1", "datasetVersionId": 12,
  "earlyStop": true, "patience": 2
}
```

校验：epochs 1–5、samples 1000–60000、batchSize ∈ {32,64,128}、lr (0,1]、seed ≥ 0、
photoRatio [0,1]、patience 1–10；`datasetVersionId` 必须属于该数据集且 READY。

### 6.2 状态机

```
QUEUED ──worker 开始──▶ RUNNING ──成功──▶ SUCCEEDED
   │                        │
   └──入队失败──▶ FAILED    └──异常/超时──▶ FAILED（attempt+1，最多重投 1 次）
```

| 状态 | 触发 | 可重复回调 |
|---|---|---|
| QUEUED | 创建成功、已入队 | — |
| RUNNING | worker 开始训练（每次回调都带 attempt） | 是（同 attempt 幂等） |
| SUCCEEDED | 训练完成并登记模型 | 是（终态不再改） |
| FAILED | 入队失败、训练异常、超时 | 是（终态不再改） |

回调 `POST /internal/v2/training/{id}/state`，body：

```json
{ "state": "RUNNING", "attempt": 1, "metrics": [...] }
{ "state": "SUCCEEDED", "attempt": 1, "modelVersion": "...", "artifact": "...", "sha256": "...",
  "sizeBytes": 12345, "metrics": {...} }
{ "state": "FAILED", "attempt": 1, "errorCategory": "TIMEOUT", "message": "..." }
```

### 6.3 事件流

| 事件 | 载荷 | 说明 |
|---|---|---|
| `task` | 任务视图（状态、指标、产物） | 任务创建/状态变化/每轮回调都会推 |
| `ping` | 空 | 心跳，前端据此判断连接可用 |

前端兜底：SSE 不可用时退化为 4 秒轮询 `GET /admin/training/tasks`。

### 6.4 日志

`GET /admin/training/tasks/{id}/logs` 读 Redis `training:log:<id>`（最多 2000 行，7 天过期）。

## 7. 服务层职责与事务边界

| 服务 | 职责 | 事务 |
|---|---|---|
| `TrainingService` | 任务创建/校验/入队、状态回调、产物登记 | 创建与回调各自 `@Transactional` |
| `DatasetService` | 数据集、版本构建、样本删除、版本删除、认领识别样本 | 建版本与删除 `@Transactional` |
| `ImportWizardService` | 格式探测、试运行、导入、批次、回滚、裁字脚本调用 | 导入 `@Transactional`，文件写盘在事务内完成后再提交 |
| `DatasetImportService` | 文件夹批量导入（逐张校验 + 去重） | 单批 `@Transactional` |
| `CollectedSampleService` | 样本落盘、去重、读取原图、孤儿清理 | 写入 `@Transactional`；清理只在引用为 0 时删文件 |
| `ModelAdminService` | 注册/激活/停用/删除模型，同步注册表 | `@Transactional` + 注册表文件写 |
| `RecognitionService` | 识别、幂等、限流、采集 | 识别落库 `@Transactional` |
| `CatalogueService` | 模型与数据集只读视图、生效模型解析 | 无写操作 |

**跨系统一致性**：入队失败会把任务置 FAILED（不留在 QUEUED）；模型产物登记失败则任务 FAILED，
不会出现「任务成功但模型不存在」。

## 10. 关键时序（文字版）

**识别（单字）**
```
前端 → POST /recognitions (multipart, requestId)
  → 限流检查（t_rate_window）→ 幂等检查（requestId）
  → ImageValidator → 模型服务 /predict
  → 写 t_recognition_v2 → 返回 digit/confidence/accepted
```

**导入（zip）**
```
前端 → POST /datasets/import-wizard/zip-preview (multipart)
  → 解压到临时目录 → 扫描/识别格式 → 试运行统计 → 返回 token
前端 → POST /datasets/{id}/import-wizard/zip {token}
  → 逐张校验/去重/落盘 → 写样本（带 batchId）→ 删临时目录
```

**训练**
```
前端 → POST /admin/training/tasks → 校验 → 导出 training-data/v<id> → 入队
worker → 训练 → 每轮回调 RUNNING（metrics）→ 成功回调 SUCCEEDED（产物）
后端 → 登记 t_v2_model → SSE 推送任务视图
```

## 11. 限流与配额

| 维度 | 实现 | 说明 |
|---|---|---|
| 识别频次 | `t_rate_window` 固定窗口计数 | 超限返回 `RATE_LIMIT`（429） |
| 并发 | 进程内信号量 / 队列长度 | 超限返回 `CONCURRENCY_LIMIT` |
| 空间与数据集数量 | `WORKSPACE_LIMIT`、创建前计数 | 平台级上限，按配置 |

## 12. 已知限制

| 限制 | 影响 | 计划 |
|---|---|---|
| SSE 票据存进程内 | 多实例部署时订阅可能落到没有票据的实例 | W8 前改 Redis Pub/Sub 或粘性会话 |
| 导入同步执行 | 大 zip 会占用请求线程 | P1 异步化 + 进度接口 |
| 训练重投上限 1 次 | worker 反复崩溃时任务会直接失败 | 视压测结果调整 |
| 无分布式事务 | 产物登记与队列状态靠补偿 | 现有回调已覆盖，超时任务由 `TASK_STALE_ATTEMPT` 兜底 |
