# W2 本地运行说明

面向 M1–M5 开发与集成成员。当前为本地未发布实现；是否实测通过以 [交付与验证记录](W2-交付与验证记录.md) 为准，不把启动命令视为启动成功记录。

## 1. 运行前置条件

- Java 17、Maven、Node.js 22+、Python 3.11、MySQL 8。
- **新建专用空库**，不要将 W2 应用直接指向已有 W1/未知数据库；已有 W1 的显式备份/校验/baseline 流程见 [后端指南](../backend/README.md)。
- 真实 full checkpoint，外部文件，不提交到 Git，不在启动时联网下载：
  - 外部标识：`mnist-cnn-w1`，版本 `w2-canvas-photo-3epoch`。
  - 预处理：`adaptive-mnist-v2`。
  - SHA256：`72e27abd7440c47dce6196f0624d82704935297adbbd4da86edb4418fafed2aa`。
  - 大小：1,689,984 bytes。不能用 smoke 权重替代。
- 为新环境单独生成 `V2_JWT_SECRET`（至少32 UTF-8字节且不同于旧 `JWT_SECRET`）、`MODEL_INTERNAL_TOKEN`、数据库密码。不要把真实值写入文档、日志或命令示例。
- 2026-11-03 已获准并完成独立MySQL/Python环境准备和本机联调；环境和结果见交付记录。测试服务验证结束后已停止，下面的命令不是当前仍在运行的承诺。

## 2. 分进程本地开发

### MySQL / Java

1. 使用专用 MySQL 8 实例/空库 `hdr_w2`，应用账号只获该库所需权限；建议仅绑定 `127.0.0.1`。不安装系统服务、不清空旧库。
2. 在启动 Java 的终端设置下表变量。
3. 从 `backend/` 执行 `mvn spring-boot:run`；Flyway 是唯一迁移入口，依次执行 V1/V2/V3。禁止再执行旧 schema 初始化脚本或开启自动 baseline。

| 变量 | 值/说明 |
|---|---|
| `DB_URL` | `jdbc:mysql://127.0.0.1:<端口>/hdr_w2?serverTimezone=UTC&allowPublicKeyRetrieval=true&useSSL=false`，仅用于本机隔离开发；远程生产需TLS |
| `DB_USERNAME`、`DB_PASSWORD` | 专用应用账号及其密码 |
| `SERVER_ADDRESS`、`SERVER_PORT` | 默认 `127.0.0.1` / `8080` |
| `V2_JWT_SECRET` | 独立随机签名密钥 |
| `MODEL_SERVICE_URL` | 默认 `http://127.0.0.1:5001` |
| `MODEL_INTERNAL_TOKEN` | 与 Python 相同，不能发送给客户端 |
| `W2_MAX_WORKSPACES` | 默认3，包含个人空间，实际强制执行 |
| `W2_RECOGNITION_PER_MINUTE` | 默认60，每用户/空间固定窗口；另有全局/IP/并发保护 |
| `W2_MAX_MEMBERS` | 默认5，仅后续成员邀请预算；W2未提供邀请接口 |
| `W2_DAILY_RECOGNITION_LIMIT` | 默认1000，仅预算；`dailyQuotaEnforced=false` |

默认 `HDR_LEGACY_AUTH_ENABLED=false`、`HDR_LEGACY_BOOTSTRAP_ENABLED=false`，没有已知密码管理员。运营账号按后端指南受控提升，旧 ADMIN 不会自动升权。

### Python

在取得新增依赖安装许可后，按 [模型服务指南](../model-service/README.md) 为 **独立新环境** 安装推理依赖。不要修改已有 W1/Conda 环境，也不要拼接多个虚拟环境的 `sys.path`。

在模型进程环境中设置：

- `MODEL_CHECKPOINT_PATH`：上述校验权重的绝对路径。
- `MODEL_INTERNAL_TOKEN`：与 Java 一致的内部凭据。
- `HOST=127.0.0.1`、`PORT=5001`。

从仓库根目录使用新环境解释器执行 `python -I model-service/serve.py`。内部 ready 只有认证成功且可信权重加载成功才返回 UP。权重或依赖缺失返回不可用，不产生随机/mock预测。

### 网页和小程序

- `frontend/`：依赖已安装时执行 `npm run dev`，访问 `http://127.0.0.1:5173`；Vite 代理到 Java 的 IPv4 loopback 地址。
- 网页先注册普通账号；注册成功应有个人空间，再进入识别页书写。
- 小程序导入 [miniprogram/](../miniprogram/)，使用相同平台账号，见其 [README](../miniprogram/README.md)。未配置服务也可以使用匿名本地画板原型，它不联网。
- 微信开发者工具/真机联调需要真实工具环境、域名或受控局域网配置。手机的 `127.0.0.1` 指手机自身；不要为了绕过这一点直接把 MySQL/Python 或所有服务开放到公网。当前没有代用户开放监听或修改 AppID/private 配置。

## 3. Compose（配置已写入，尚未运行验证）

1. 将根 `.env.example` 复制为本地 `.env`，补齐所有空的必填值；缺值会显式失败。
2. `MODEL_CHECKPOINT_PATH` 使用实际文件的绝对路径，Compose 以只读文件挂载，并关闭自动创建缺失源路径。
3. 在具备 Docker 且允许拉取/构建镜像的环境再执行 `docker compose up --build`。本次没有运行 Docker。

只有 `127.0.0.1:8088`（可用 `WEB_PORT` 调整）映射到网页；MySQL、Redis、Java、Python **均不发布主机端口**。Java 和 Python 在容器网络内显式监听 `0.0.0.0`，不等于发布到公网。W2使用独立 `mysql-w2-data` 卷，不复用 W1 数据卷、不挂载旧 schema.sql。Redis 是 `future-training` profile，不参与 W2 必需依赖，状态页显示 NOT_CONFIGURED。

限流以 Java 实际连接对端 IP 为准，不信任客户端提供的 `X-Forwarded-For`。通过 Nginx 时 IP 窗口由同一代理的访问者共享，这是当前保守的开发配置；日配额对账、可信代理边界和多实例治理在后续迭代完善。

## 4. 测试命令和验收顺序

从各模块目录执行：

```text
backend:       mvn -B clean verify
frontend:      npm test && npm run build
miniprogram:   npm test
model-service: python -I -m pytest -q
```

上述模型全量轻量测试需要同一环境中的 Flask、Pillow、NumPy；不要把分环境子集通过称为完整 API 测试通过。

MySQL 实库测试额外设置 `W2_MYSQL_TEST_URL`（库名前缀必须 `hdr_w2_it_`）、`W2_MYSQL_TEST_USERNAME`、`W2_MYSQL_TEST_PASSWORD`，运行 `mvn -B -Pmysql-it verify`。测试在隔离实例创建随机同前缀库，仅清理自身成功创建的库；传入的模板库不被清空。测试账号需有该前缀的建库/表/约束权限，不能使用生产连接。回滚故障注入采用表级CHECK约束，不要求SUPER或放宽全局binlog设置。

真实权重测试需设置 `HDR_TEST_CHECKPOINT` 为绝对路径，从 `model-service/` 执行：

```text
python -I -m pytest -c pytest-inference.ini tests_inference -q
```

显式传入测试目录以避免从仓库根目录运行时误收集其他测试。未提供权重而跳过，不能计为真实推理通过。

内部验收顺序：新库/迁移 → 注册个人空间 → 两账号/成员隔离 → 内部真实推理 → 浏览器画板上传/落库 → 微信工具/设备真实识别 → 清空、空间切换、退出竞态。周四用于集中展示本周成果，不能代替会前团队内部验收。
