# 手写数字识别系统 — 团队分工与工作计划

> 团队规模：5 人　|　周期：7 周　|　开发模型：Scrum 敏捷（1 周 1 个 Sprint）　|　编制日期：2026-10-22

---

## 一、项目概述

构建手写数字识别系统：用户在屏幕上书写数字，由后端深度学习模型自动识别，准确率不低于 90%。系统支持 PC 端与手机端应用（手机端负责手写识别，PC 端负责管理性功能），并具备系统管理能力，包括模型管理、模型训练管理、用户管理与统计分析。

**核心功能**

| 功能 | 说明 |
|---|---|
| 模型训练管理 | 支持深度学习模型训练全过程可视化：数据集选择、参数设置、过程数据展示、模型保存，使简单了解深度学习的用户也能训练模型并投入使用 |
| 模型管理 | 支持多模型管理，同一时刻仅一个模型处于活跃状态，管理员可依据使用反馈调整并便捷切换生效模型 |
| 用户管理 | 用户注册、登录、角色与权限管理 |
| 统计分析 | 识别调用量、准确率、模型使用分布等统计 |

**增强功能**：支持连续手写数字识别，**本期目标固定为最多 4 位数字**（超出 4 位不在验收范围；4 位内按整串正确率验收，见 W5/W6）。

> 版本范围说明：W1–W7 交付的是一个**单部署实例**（管理员运维、用户使用）。真正的公共 SaaS 化（多租户、数据集上传与标注、存储配额、计费、托管 broker）**不在 W1–W7 范围内**，另见文末「W8+：SaaS 化路线」。

**技术约束**：系统主体基于 Java 实现，模型端基于 Python 实现；建议采用 Spring Boot + Vue + Flask；数据集为 MNIST 及扩展数据集；模型可采用现有 CNN 模型。

**主要难点**：Java 与 Python 异构系统集成、模型训练过程可视化。

## 二、关键技术决策

| 决策点 | 建议方案 | 理由 |
|---|---|---|
| 手机端形态 | **微信小程序** | 免安装、答辩演示方便、画板 + 接口调用即可实现；独立 APP 需打包签名，7 周内性价比低 |
| 异构集成方式 | Python 侧 **Flask 提供 REST 接口 + Celery/Redis 任务队列**，Spring Boot 作为唯一对外网关 | 训练属长耗时任务必须异步；Java 统一鉴权，Python 仅作内部服务 |
| 准确率 ≥90% 的保障 | 不依赖 MNIST 测试集（指标虚高至 99%），而以**自采手写数据 + 图像预处理归一化**为准 | 小程序画板输入与 MNIST 数据分布差异大，是真实风险点，需从第 3 周开始采集数据 |

**系统分层**

```
微信小程序  ─┐
             ├─→ Spring Boot 网关（鉴权 / 业务 / 文件） ─→ Flask 模型服务（推理 / 训练）
Vue 管理端  ─┘                │                                  │
                          MySQL + Redis                  任务队列 / 模型文件
```

## 六、敏捷执行机制

### 6.1 协作规范

- **看板工具**：飞书 / 钉钉多维表格或 Jira，列设置为 `Backlog → 本周 Sprint → 进行中 → 待评审 → 已完成`；每人同时进行中的任务不超过 2 张。
- **分支策略**：`main`（随时可发布）/ `develop`（集成分支）/ `feature/xxx`（功能分支）；合并必须走 Merge Request，且至少 1 人 Code Review。
- **完成定义（DoD）**：代码已合并 + 接口/文档已更新（含 Wiki）+ 自测通过 + **已通过团队内部验收、可在周四集中展示时现场演示**。四条缺一不算完成。
- **交付要求**：每个 Sprint 结束必须产出可运行的增量，不接受"代码写了一半"。

## 七、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| Java-Python 异构集成踩坑 | 阻塞全局进度 | **W1 安排 2 天技术验证 Spike**，先跑通"Java 传图 → Python 返回结果"再进入正式开发 |

## 十、W8+：SaaS 化路线（按波次切分）

> W1–W7 交付的是**单部署实例**：一个运维方（SUPER_ADMIN）管模型与训练，终端用户只做识别。
> 公共 SaaS 需要多租户、用户自带数据、配额计费与更严格隔离，体积远超剩余工期，因此**单独排期**，
> 并按下表**切成四个波次**，每波结束都能独立演示、独立验收，不把风险堆到最后。

### 10.0 负荷评估与切分原则

先按"能不能在本机验证"给每个工作包定性，这是切分的依据：

| 工作包 | 粗估工期 | 可验证性 | 结论 |
|---|---|---|---|
| 租户实体与可见性 | 3–4 天 | 本机可验证（接口 + 集成测试） | **W8** |
| 带标注数据集上传（ZIP + manifest） | 3–5 天 | 本机可验证 | **W8** |
| 训练按租户解析与隔离 | 2–3 天 | 本机可验证 | **W8** |
| 样本回流（用户确认标签） | 2–3 天 | 本机可验证 | **W9** |
| 数据集版本化与审核 | 3 天 | 本机可验证 | **W9** |
| 队列按租户配额与公平调度 | 3–4 天 | 本机可验证（单 worker 单并发） | **W9** |
| 完整标注界面（逐图标注/批量） | 5–7 天 | 本机可验证但工作量最大 | **W10** |
| 存储配额与生命周期 | 4–5 天 | 本机可验证（需自建清理任务） | **W10** |
| 用量计量（识别次数/训练时长/存储） | 3–4 天 | 本机可验证 | **W10** |
| 账单与套餐 | 4–6 天 | 需商用决策（定价策略） | **W11+** |
| 托管 broker + 多并发 worker | 5–8 天 | **本机无法验证**（需云环境/Linux） | **W11+** |
| 监控告警 + 审计日志 | 4–6 天 | 需真实运行环境 | **W11+** |
| 合规与渗透测试 | 外部依赖（法务/工具） | 无法自测 | **W11+** |
| 连笔/粘连数字串（CTC） | 1–2 周 | 需大量真实数据 | **W9**（与回流数据一起） |
| 超过 4 位数字 | — | 收益低 | 不做 |

切分原则：

1. **每波必须能独立演示**，不允许"半波"（接口写完但没法用不算交付）。
2. **依赖本机无法验证的资源**（云 broker、托管数据库、真实站点托管）一律后置，不早做。
3. **先窄后宽**：先支持 0–9、最多 4 位、间隔式书写；连笔与更长串后置。
4. **数据优先于界面**：没有真实样本，标注界面做得再好也训不出东西，所以回流先于完整标注界面。

### 10.1 为什么不能"只加一个上传接口"

监督训练需要标签，用户上传的原始图片没有标注就无法训练。数据集能力是一条完整链路：

```text
上传 → 格式/大小/数量校验 → 标注（自带 label 或平台标注）
     → 版本化 → 训练引用 → 租户隔离与配额 → 保留/删除 → 审计
```

缺任一环，功能要么不可用（无标签）、要么不安全（任意文件）、要么留下合规隐患（无生命周期）。

### 10.2 已经具备的前置能力（W1–W7 沉淀）

|---|---|

### 10.3 波次划分与验收

| 波次 | 周次 | 交付内容 | 里程碑 |
|---|---|---|---|
| **Wave A 最小租户化** | W8 | 租户/组织实体、成员角色、租户级可见性；带标注数据集上传（ZIP + manifest + 安全检查 + 登记为租户数据集）；训练按租户解析数据集、产物仅本租户可见 | **SaaS-1** |
| **Wave B 数据闭环** | W9 | 识别样本回流（用户确认正确答案并同意入库）、数据集版本化与审核、队列按租户配额；**连笔/粘连（CTC）识别**基于这批真实数据再做 | **SaaS-2** |
| **Wave C 可运营** | W10 | 存储配额与保留/删除策略、用量计量（识别次数/训练时长/存储）、完整标注界面 | **SaaS-3（不含账单）** |
| **Wave D 生产化** | W11+ | 托管 broker + 多并发 worker + 消息持久化、监控告警、审计日志、账单与套餐、合规与渗透测试 | **SaaS-4** |

验收口径：

| 里程碑 | 验收标准 |
|---|---|
| **SaaS-1**（W8） | 两个租户互不可见；A 上传的带标注数据集只能训出 A 可见的模型；越权访问返回 403/404 而不是静默过滤 |
| **SaaS-2**（W9） | 用户上传未标注样本 → 回流确认标签 → 审核入库 → 训练 → 产物仅本租户可激活；连笔数字串给出实测整串准确率（不承诺达标） |
| **SaaS-3**（W10） | 配额生效、超额拒绝有明确错误码；删除链路可演示（数据与产物都不可再访问）；用量可查 |
| **SaaS-4**（W11+） | 托管 broker + 多并发压测通过；监控告警可触发；审计日志可追溯；账单可导出 |

### 10.4 明确不做（任何波次都不承诺）

- 任意格式/任意场景 OCR（仍限定 0–9、最多 4 位）。
- 超过 4 位数字、表格/公式混合版面。
- 平台代客大规模人工标注服务。
- 跨租户的模型市场或模型交易。

### 10.5 与 W1–W7 的衔接约束

- W1–W7 的"单实例"假设（全局 SUPER_ADMIN、训练全局队列、`t_v2_model.scope=PUBLIC`）在 Wave A/B 要重新审视，**不能靠加过滤条件糊过去**。
- W4 明确挂起的「多并发 + 托管 broker」在 Wave D 收口，届时另立验证记录，不沿用本机 solo + 二进制 Redis 的结论。
- **数据依赖前置**：W5 结束前必须有 ≥1000 条真实手写样本（画板 + 相册两类），否则 W6 的"单字与 4 位串 ≥90%"无法验收，只能如实报告实测值并标注未达标；Wave B 的连笔识别同样依赖这批数据。

### 10.6 W1–W7 内部的减负调整（因 4 位口径加码）

明确 4 位串验收后，W5/W6 的负荷上升，按同一原则顺延非关键项：

| 原计划 | 调整 |
|---|---|
| W5 统计看板（多模型分布、时间趋势、复杂图表） | 只保留基础三项（调用量/准确率/模型分布）+ 简单图表；**完整看板与高级图表顺延 W10** |
| 连续识别（不限位数、含连笔） | 收紧为 **1–4 位、间隔式书写**；连笔/CTC **顺延 W9** |
| 模型血缘（A→B→C 训练链）可视化 | **顺延 W10** |
| W6 自采数据微调 | 保留，但若样本不足，验收口径改为"如实报告实测值与缺口"，**不伪造达标** |
