# 手写数字识别系统 — 团队分工与工作计划

> 团队规模：5 人　|　周期：7 周　|　开发模型：Scrum 敏捷（1 周 1 个 Sprint）　|　编制日期：2026-10-22

---

## 一、项目概述

构建手写数字识别系统：用户在屏幕上书写数字，由后端深度学习模型自动识别，准确率不低于 90%。系统支持 PC 端与手机端应用（手机端负责手写识别，PC 端负责管理性功能），并具备系统管理能力，包括模型管理、模型训练管理、用户管理与统计分析。

**核心功能**

| 功能 | 说明 |
|---|---|
| 模型训练管理 | 支持深度学习模型训练全过程可视化：数据集选择、参数设置、过程数据展示、模型保存，使简单了解深度学习的用户也能训练模型并投入使用 |
| 模型管理 | 支持多模型管理，同一时刻仅一个模型处于活跃状态，管理员可依据使用反馈调整并便捷切换生效模型 |
| 用户管理 | 用户注册、登录、角色与权限管理 |
| 统计分析 | 识别调用量、准确率、模型使用分布等统计 |

**增强功能**：支持连续手写数字识别，**本期目标固定为最多 4 位数字**（超出 4 位不在验收范围；4 位内按整串正确率验收，见 W5/W6）。

> 版本范围说明：W1–W7 交付的是一个**单部署实例**（管理员运维、用户使用）。真正的公共 SaaS 化（多租户、数据集上传与标注、存储配额、计费、托管 broker）**不在 W1–W7 范围内**，另见文末「W8+：SaaS 化路线」。

**技术约束**：系统主体基于 Java 实现，模型端基于 Python 实现；建议采用 Spring Boot + Vue + Flask；数据集为 MNIST 及扩展数据集；模型可采用现有 CNN 模型。

**主要难点**：Java 与 Python 异构系统集成、模型训练过程可视化。

## 二、关键技术决策

| 决策点 | 建议方案 | 理由 |
|---|---|---|
| 手机端形态 | **微信小程序** | 免安装、答辩演示方便、画板 + 接口调用即可实现；独立 APP 需打包签名，7 周内性价比低 |
| 异构集成方式 | Python 侧 **Flask 提供 REST 接口 + Celery/Redis 任务队列**，Spring Boot 作为唯一对外网关 | 训练属长耗时任务必须异步；Java 统一鉴权，Python 仅作内部服务 |
| 准确率 ≥90% 的保障 | 不依赖 MNIST 测试集（指标虚高至 99%），而以**自采手写数据 + 图像预处理归一化**为准 | 小程序画板输入与 MNIST 数据分布差异大，是真实风险点，需从第 3 周开始采集数据 |

**系统分层**

```
微信小程序  ─┐
             ├─→ Spring Boot 网关（鉴权 / 业务 / 文件） ─→ Flask 模型服务（推理 / 训练）
Vue 管理端  ─┘                │                                  │
                          MySQL + Redis                  任务队列 / 模型文件
```

## 六、敏捷执行机制

### 6.1 协作规范

- **看板工具**：飞书 / 钉钉多维表格或 Jira，列设置为 `Backlog → 本周 Sprint → 进行中 → 待评审 → 已完成`；每人同时进行中的任务不超过 2 张。

## 十、W8+：SaaS 化路线

> W1–W7 交付的是**单部署实例**：一个运维方（SUPER_ADMIN）管模型与训练，终端用户只做识别。
> 真正的公共 SaaS 需要多租户、用户自带数据、配额计费与更严格的隔离，体积远超剩余工期，因此**单独排期，不并入 W1–W7**。

### 10.1 为什么不能"只加一个上传接口"

监督训练需要标签，用户上传的原始图片没有标注就无法训练。所以数据集能力是一条完整链路：

```text
上传 → 格式/大小/数量校验 → 标注（自带 label 或平台标注）
     → 版本化 → 训练引用 → 租户隔离与配额 → 保留/删除 → 审计
```

缺任一环，功能要么不可用（无标签）、要么不安全（任意文件）、要么留下合规隐患（无生命周期）。

### 10.4 里程碑与验收口径

| 里程碑 | 验收标准 |
|---|---|
| **SaaS-1** 多租户可用（S1–S2） | 两个租户互不可见；A 租户上传的带标注数据集可训出仅 A 可见的模型 |
| **SaaS-2** 标注与训练闭环（S3–S4） | 用户上传未标注样本 → 标注 → 训练 → 产物仅本租户可激活 |
| **SaaS-3** 可运营（S5–S6） | 配额生效、超额拒绝有明确码；账单可导出 |
| **SaaS-4** 生产就绪（S7–S8） | 托管 broker + 多并发压测通过；审计与删除链路可演示 |

### 10.5 明确不做（W8+ 也不承诺）

- 任意格式/任意场景 OCR（仍限定 0–9、最多 4 位）。
- 平台代客标注的大规模人工标注服务。
- 跨租户的模型市场或模型交易。

### 10.6 与 W1–W7 的衔接约束

- W1–W7 的任何"单实例"假设（全局 SUPER_ADMIN、训练全局队列、`t_v2_model.scope=PUBLIC`）在 S1/S4 中都要重新审视，不能靠加过滤条件糊过去。
- W4 明确挂起的「多并发 + 托管 broker」在 S7 收口，届时另立验证记录，不沿用本机 solo + 二进制 Redis 的结论。
