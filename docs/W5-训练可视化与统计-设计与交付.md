## 2. 实时推送怎么工作

```text
前端 POST /api/v2/admin/training/tasks/events/ticket  （Bearer 鉴权）
      ← {ticket, expiresInSeconds:120}               一次性、120 秒过期
前端 EventSource GET /api/v2/admin/training/tasks/events?ticket=***
      ← event: ready
      ← event: task  {TaskView JSON}   创建/排队/运行/成功/失败都推
```

为什么用票据而不是直接带 token：浏览器的 `EventSource` **不能设置请求头**，把 JWT 放进 URL 会进访问日志。票据是一次性的、短寿命、且绑定用户，只能用来订阅事件流。

失败兜底：`EventSource` 不可用或票据失败时，训练页回落到原有 4 秒轮询，页面标题会显示"实时推送不可用，使用 4 秒轮询"。

每轮指标怎么到前端：worker 每跑完一轮就回调 `POST /internal/v2/training/{id}/state`（`RUNNING` + `metrics`），Java 写 `t_v2_training_metric` 并把该任务的 `TaskView` 推出去；`TaskView.metrics.history` 在任务未完成时由逐轮表拼出，前端直接画。

## 3. 统计口径（重要）

| 指标 | 来源 | 说明 |
|---|---|---|
| 识别请求 | `t_recognition_v2` 行数 | 含失败与拒识 |
| 返回结果 | `status='SUCCEEDED'` | 真正给出了数字 |
| 拒识 | `failure_code='UNRECOGNIZED_INPUT'` | 策略主动拒绝 |
| 服务失败 | `status='FAILED'` 且码不是拒识 | 模型服务异常、超时等 |
| 平均耗时 | `AVG(processing_ms)` | 模型调用 + 预处理 |
| 模型分布 | 按 `model_version` 分组 | 切换模型后能看出使用比例 |

**为什么没有准确率**：生产请求没有人工标注，任何"准确率"都只能是猜测。统计页与接口都返回同一句声明；准确率只来自离线评测报告（`docs/` 下的评估记录）。

**新增 V9 迁移**：`t_recognition_v2.failure_code` + `(workspace_id,status,created_at)` 索引。没有这一列时，拒识和服务失败会混成一个 FAILED，统计无法拆分。历史数据没有该列，会落在"服务失败"里——这是事实，不做回填推测。

## 4. 联调实测（真实 Java + 真实模型服务 + 真实 Celery worker）

脚本 `.git/w2-local/w5-live-smoke.py`，13 项断言全过：


## 6. 交互细节（实测后调整过）

| 项 | 结果 |
|---|---|
| 曲线位置 | 从"表格下方固定一块"改为**插在所选任务行下方**（`colspan` 展开行），再点同一行收起；图表标题仍写任务号，位置与数据一一对应 |
| 曲线组件 | 独立组件 `training/TrainingCurve.vue` 自己持有宿主 ref 与实例。**踩过的坑**：在 `v-for` 里用字符串 `ref` 拿到的是数组而不是 DOM，`echarts.init` 会静默失败、页面只剩空白 |
| 空状态 | 任务尚无逐轮指标时显示"该任务还没有逐轮指标"，不画空坐标系；容器宽度为 0 时最多重试 10 次再报错 |
| 最近识别 | 统计页新增表格：时间、结果（数字/拒识/失败）、置信度、耗时、模型、来源；**空间范围只返回本人记录**，平台范围需 SUPER_ADMIN 且多一列空间 |
| 平台状态 | `health-summary` 四项全部现场探测：MySQL 查询、模型服务 `/ready`、Redis `PING`、训练 worker 心跳键（15s TTL，worker 每 3s 刷新），并显示排队/运行中数量 |
| 复选框 | 全局 `input` 规则（`min-height:42px`）会把 checkbox 撑成大方块，已单独约束为 16px |

## 7. 已知限制（不掩盖）

- **本机 esbuild 构建被拦**：`vite build` 报 `[vite:esbuild-transpile] remove D:\Temp\esbuild-...: Access is denied`（安全软件占用临时文件）。已用 `--config`（关闭 esbuild、不压缩）验证代码可构建（exit 0），但**正式压缩构建未在本机验证**，需在干净环境或关闭安全软件后复跑。
- SSE 是单机内存广播：多实例部署时（W8+）需要换成 Redis pub/sub 或消息总线，当前实现不跨进程。
- 前端曲线在任务运行中每轮刷新一次，没有做节流/虚拟化；任务很多时列表未分页（limit 20）。
- 最近识别表格最多 50 条、按 id 倒序，没有分页与筛选；空间维度刻意只给本人记录。
- 统计只有 7/30/90 天窗口与两种范围，没有自定义区间、没有导出。
- 训练任务的 `metrics.history` 在运行期来自逐轮表（每次详情/列表查询会多一条按主键前缀的查询，量小可接受）；任务完成后仍以最终 JSON 为准。
