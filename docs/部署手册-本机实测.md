```powershell

```

表结构不用手工建：后端启动时 Flyway 自动执行到当前最新（V1–V23）。

### 1.6 建第一个管理员（新库没有内置账号）

注册接口创建的账号 `platform_role` 固定是 `USER`，模型管理/训练页需要 `SUPER_ADMIN`。
推荐用环境变量引导（后端启动时自动补，幂等）：

```powershell
# scripts/.env 里填好，然后正常启动；已有同名账号且是 SUPER_ADMIN 时不做任何改动
$env:HDR_BOOTSTRAP_ADMIN_USERNAME = 'admin'
$env:HDR_BOOTSTRAP_ADMIN_PASSWORD = '换成强密码'
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1
# 日志会出现：已创建引导管理员 'admin'（SUPER_ADMIN）…
```

> 行为：账号不存在 → 直接建为 `SUPER_ADMIN`（bcrypt 存储，不发会话）；账号已存在但不是超管 → 提权（不改密码）。
> **建成后请立即改密码，并从 `scripts/.env` 删掉这两行。**
> 也可以用 SQL 兜底：`UPDATE t_user SET platform_role='SUPER_ADMIN' WHERE username='admin';`
>
> 注意：`scripts/.env` 里如果留了 `HDR_BOOTSTRAP_ADMIN_USERNAME=`（空值），它不会清掉你已经导出的同名变量——
> 空值视为"未配置"；但**非空值会覆盖**进程里的旧值（这是 .env 优先的策略）。

> 原任务的"管理员账号 admin / HdrAdmin2026!"来自原作者本机已有的库；**空库部署时必须走上面这一步**，否则进不了模型/训练页面。

## 2. 起停

```powershell
# 起（顺序：MySQL → Redis → 模型服务 → 后端 → 训练 worker → 前端，每步都做健康探测）
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1

# 起并强制重新构建后端 jar / 安装前端依赖
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1 -Build

# 只做识别、不跑训练
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1 -SkipWorker

# 停（反向顺序；只杀本项目进程，不误伤其它 MySQL/Redis/Java）
powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1
```

脚本行为要点：

- 端口已被本项目占用时**跳过启动**，可以重复执行；
- 失败立即打印该服务日志尾部并返回非 0，不会留下"半残"状态；
- 日志写到 `$HDR_RUNTIME\logs\<service>.out.log / .err.log`，PID 写到 `$HDR_RUNTIME\run\<service>.pid`；
- `.env` 里的值**优先于**当前进程里已有的同名变量（本机 `JAVA_HOME` 指向 JDK 11，不覆盖会起不来）；要保留现有变量加 `-KeepProcessEnv`；
- `stop-all.ps1` 终止前会复核"映像名 + 命令行特征"，并排除自身进程链（早期版本按命令行匹配时曾命中 PID 已回收的无关进程）。

# 演练（不碰现网库）：备份 → 导入临时库 → 逐表比对行数与 CHECKSUM → 清理临时库

备份文件落在 `$HDR_RUNTIME\backup\hdr-<schema>-<时间戳>.sql`。

> 需要用管理员账号（要建/删临时库），在 `scripts/.env` 里配 `MYSQL_ADMIN_USER` / `MYSQL_ADMIN_PASSWORD`；

## 7. 常见故障（本机实测补充）

| 现象 | 原因 / 处理 |
|---|---|
| 后端启动即 `UnsupportedClassVersionError … class file version 61.0` | 用了系统里的 `JAVA_HOME`（JDK 11）。`.env` 里指定 JDK 17，或 `-KeepProcessEnv` 不要开 |
| worker 启动即 `redis.exceptions.ResponseError: … ERR syntax error` | kombu ≥ 5.7 用了 `ZADD … GT`（Redis 6.2+）。装 `model-service/requirements-worker.txt` 固定版本 |
| worker 报 `No module named 'models'` | worker 用了 `python -I`（隔离模式把 cwd 移出 `sys.path`）。`start-all.ps1` 已去掉 `-I` |
| 训练报 `--data-dir must contain official MNIST IDX files` | 没跑 `scripts/fetch-mnist.py`，或目录里只有 `.gz` 压缩包 |
| 识别一律返回 400 `图片未通过模型服务校验` | 旧版本会把所有模型服务 4xx 都报成这个。现在已按原因分码（见下两行），若仍看到这条说明响应的 400 没有已知 category |
| 识别返回 503 `当前生效的模型在模型服务注册表中不存在…` | 数据库里的生效模型版本没有对应权重：按 1.4 拉权重后，在"模型管理"里注册并激活 Release 里的版本。这就是新装环境的必踩点（第 8 节 1） |
| 识别返回 400 `请先书写数字，不能识别空白图片` | 画板是空的（`BLANK_IMAGE`），不是图片格式问题 |
| 识别返回 422 `无法可靠识别这个数字` | 选择性识别策略（置信度 < 0.90 或 margin < 0.85 就拒识）。整页截图、弱模型都会触发；用画板导出的白底黑字图 |
| 识别返回 429 | 触发限流：每用户 `W2_RECOGNITION_PER_MINUTE`（默认 60/分钟）、全平台 `W2_GLOBAL_RECOGNITION_PER_MINUTE`（默认 240/分钟，原为写死） |
| 注册返回 429 | 注册接口按 IP 限流（默认 5 次/15 分钟）：`W2_REGISTER_PER_IP` / `W2_REGISTER_WINDOW_SECONDS`。压测前调大，生产保持默认 |
| 训练任务一直停在 RUNNING，worker 日志 `callback failed: 500 … INTERNAL_ERROR` | 后端的模型注册被内层事务标记 rollback-only（`UnexpectedRollbackException`）。最常见触发：训练产物版本号与已发布基线**撞名**（都是 `w4-task-8-a1`），注册时冲突。查后端日志确认，并按 P0 交付记录第 10 节恢复基线 |
| 已发布基线的 `checkpoint.pt` 被训练结果覆盖 | 同上撞名问题的后果。用 `scripts/fetch-weights.ps1 -ForceRegistry` 恢复，再 `POST /api/v2/admin/models/registry/reload` 让模型服务重读 |
| 前端 5173 突然掉线，`frontend.err.log` 里有 `EBUSY … watch … .tmpdir\\format.js.tmp` | Windows 上编辑器/工具原子保存会在 `src/` 下建临时目录，Vite 的 watcher 撞上就退出。重新执行 `start-all.ps1` 即可（它只起缺失的服务） |
| 后端打包失败 `repackage` / `Unable to rename …jar` | 后端进程占用 jar：先停后端。**跑 `-Pmysql-it` 集成测试时只停后端与 worker，别用 stop-all**（它会把 MySQL 一起停掉，IT 直接 `Connection refused`） |
| 模型对比报「对比图片与标签数量必须一致」 | 旧版本把 `t_v2_dataset_sample.label`（VARCHAR）当数字强转，异常被跳过分支吞掉导致图片/标签错位；已在 `labelOf()` 里兼容字符串，若仍出现请检查样本文件是否可读 |
| `npm ci` 退出码 1 但依赖装好了 | npm 11 对 install 脚本的新策略，用 `npm run build` 能过就无影响 |
| 训练 `samples 必须在 1000..60000` / `batchSize 必须是 32/64/128` 等 | 训练参数是白名单校验；缺字段的报错现在会明确写"该字段没有服务端默认值，必须显式传入" |
