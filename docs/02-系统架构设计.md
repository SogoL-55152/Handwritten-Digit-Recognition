# 手写数字识别系统 — 系统架构设计 v0.1

> 编制日期：2026-10-22　|　状态：初稿（W1）

## 1. 总体架构

```
┌──────────────┐        ┌──────────────┐
│ 微信小程序    │        │ Vue 管理端    │
└──────┬───────┘        └──────┬───────┘
       │ HTTPS / JWT           │ HTTPS / JWT
       └──────────┬────────────┘
                  ▼
       ┌───────────────────────┐
       │ Spring Boot 网关服务   │  鉴权、用户、模型、训练任务、统计
       │  （唯一对外入口）       │
       └───────┬───────┬───────┘
               │       │
        MySQL 8│       │REST（内网）
               ▼       ▼
       ┌───────┐  ┌──────────────────────┐
       │ Redis │  │ Flask 模型服务        │
       └───┬───┘  │  推理 / 模型注册 / 训练│
           │      └──────────┬───────────┘
           │                 │
           └── Celery 任务队列 ┘
                             ▼
                     模型权重文件（volume）
```

设计原则：

1. **单一对外网关**：小程序与管理端只访问 Spring Boot；Python 服务仅在容器内网暴露（开发环境可映射 5001）。
2. **异构解耦**：Java 与 Python 之间仅通过 REST + JSON 通信；训练任务通过 Celery 异步化。
3. **状态可恢复**：训练进度写入 Redis，接口无状态，服务重启不丢任务视图。
4. **模型与业务分离**：权重文件与活跃模型状态由模型服务管理；Java 侧只保存模型元数据与外部 ID。

## 3. 关键流程

### 3.1 手写识别

```
小程序 canvas → 导出 PNG → POST /api/recognition/predict（JWT）
  → Spring Boot 校验并转发 multipart 至 Flask /api/v1/predict
  → 预处理（灰度/反色/二值化/裁剪/居中/28×28/归一化）
  → 活跃 CNN 推理 → softmax → {result, confidence}
  → Java 记录识别日志 → 返回小程序
```

### 3.2 训练任务

```
管理端 POST /api/train-tasks
  → Spring Boot 建任务（PENDING）→ Flask /api/v1/train
  → Celery 入队 → worker 训练（逐 epoch 写 Redis 指标）
  → 管理端轮询 GET /api/train-tasks/{id}/metrics（SSE 为后续优化）
  → 训练完成：保存权重 → 注册模型 → Java 同步模型元数据（SUCCESS）
  → 管理员在模型管理页启用 → Flask 激活对应权重
```

### 3.3 活跃模型切换

`POST /api/models/{id}/activate` → Java 校验模型存在且非删除 → 调用 Flask `/api/v1/models/{externalId}/activate` → 双方状态更新。若模型服务调用失败则回滚本地事务。

## 4. 技术选型与理由

| 选型 | 理由 |
|---|---|
| Spring Boot 3 + MyBatis-Plus | 团队 Java 技术栈；CRUD 效率高 |
| JWT + 拦截器 | 无状态、跨端通用；骨架阶段避免引入完整 Spring Security 的复杂度 |
| Flask + Celery + Redis | 训练长耗时必须异步；Flask 轻量，便于算法同学独立迭代 |
| PyTorch + CNN | MNIST 上成熟；便于自定义训练循环与指标上报 |
| Vue 3 + Element Plus + ECharts | 管理端组件齐全；ECharts 满足训练曲线与看板 |
| 微信小程序 | 免安装，答辩演示成本低 |
| SSE（W5）+ 轮询兜底 | 训练可视化实时性；轮询作为降级方案 |

## 5. 准确率保障策略

- 不以 MNIST 测试集 99% 作为验收依据，改用自采手写测试集（小程序画板分布）。
- 预处理与训练数据保持一致：反色、去边框、按外接框缩放至 20×20 并居中到 28×28。
- 数据增强：随机旋转 ±10°、平移 ±10%、缩放 0.9–1.1。
- W3 起持续采集样本；W6 留整周调优，目标 ≥ 90%。

## 6. 部署视图

- 开发：本机分别启动 MySQL/Redis、模型服务（5001）、后端（8080）、前端（5173），Vite 代理 `/api` 至后端。
- 测试/演示：`docker compose up -d --build` 启动 6 个服务（mysql、redis、model-service、model-worker、backend、frontend），前端 Nginx 反代 `/api`。
- 模型权重、MySQL、Redis 使用命名卷持久化。

## 7. 风险与备选

| 风险 | 备选 |
|---|---|
| Celery/Redis 环境不稳定 | `CELERY_TASK_ALWAYS_EAGER=1` 同进程执行训练（仅开发） |
| SSE 推送不稳定 | 前端 2s 轮询（当前骨架已实现） |
| 连续识别挤占工期 | W4 末评估，必要时降级为可选项 |
| 无 GPU 训练慢 | 默认 CPU + 小 epoch；演示用预训练模型 |
