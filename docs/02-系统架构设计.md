# 手写数字识别系统 — 系统架构设计 v1.0

> 编制：M1　|　日期：2026-10-24　|　状态：待团队评审确认（周四前完成）

## 1. 总体架构（目标形态）

```text
微信小程序 ─┐
             ├── HTTPS / JWT ── Spring Boot 网关 ── MySQL 8（业务数据）
Vue 管理端 ─┘                        │
                                     └── REST（内网）── Flask 模型服务
                                                           │
                                                      Redis / Celery
                                                           │
                                                       训练 worker
                                                           │
                                                       模型权重文件
```

**W1 实现边界**：Spring Boot 提供认证与健康检查；Vue 提供管理员登录与首页；小程序提供独立手写画板原型；Flask 仅提供健康检查。CNN 通过独立 CLI 离线训练，与 Flask、Redis、Celery 无依赖关系。上图中的在线推理、模型管理、异步训练和统计属于后续周目标，不代表目前已打通。

设计原则：

1. **单一对外网关**：小程序与管理端只访问 Spring Boot；Python 服务仅在容器内网暴露（开发环境可映射 5001）。
2. **异构解耦**：Java 与 Python 之间仅通过 REST + JSON 通信；训练任务通过 Celery 异步化。
3. **状态可恢复**：训练进度写入 Redis，接口无状态，服务重启不丢任务视图。
4. **模型与业务分离**：权重文件与活跃模型状态由模型服务管理；Java 侧只保存模型元数据与外部 ID。

## 3. 关键流程

### 3.1 手写识别

```
小程序 canvas → 导出 PNG → POST /api/recognition/predict（JWT）
  → Spring Boot 校验并转发 multipart 至 Flask /api/v1/predict
  → 预处理（灰度/反色/二值化/裁剪/居中/28×28/归一化）
  → 活跃 CNN 推理 → softmax → {result, confidence}
  → Java 记录识别日志 → 返回小程序
```

### 3.2 训练任务

```
管理端 POST /api/train-tasks
  → Spring Boot 建任务（PENDING）→ Flask /api/v1/train
  → Celery 入队 → worker 训练（逐 epoch 写 Redis 指标）
  → 管理端轮询 GET /api/train-tasks/{id}/metrics（SSE 为后续优化）
  → 训练完成：保存权重 → 注册模型 → Java 同步模型元数据（SUCCESS）
  → 管理员在模型管理页启用 → Flask 激活对应权重
```

### 3.3 活跃模型切换

`POST /api/models/{id}/activate` → Java 校验模型存在且非删除 → 调用 Flask `/api/v1/models/{externalId}/activate` → 双方状态更新。若模型服务调用失败则回滚本地事务。

## 4. 技术选型与理由

| 选型 | 理由 |
|---|---|
| Spring Boot 3 + MyBatis-Plus | 团队 Java 技术栈；CRUD 效率高 |
| JWT + 拦截器 | 无状态、跨端通用；骨架阶段避免引入完整 Spring Security 的复杂度 |
| Flask + Celery + Redis | 训练长耗时必须异步；Flask 轻量，便于算法同学独立迭代 |
| PyTorch + CNN | MNIST 上成熟；便于自定义训练循环与指标上报 |
| Vue 3 + Element Plus + ECharts | 管理端组件齐全；ECharts 满足训练曲线与看板 |
| 微信小程序 | 免安装，答辩演示成本低 |
| SSE（W5）+ 轮询兜底 | 训练可视化实时性；轮询作为降级方案 |

## 5. 准确率保障策略

- 不以 MNIST 测试集 99% 作为验收依据，改用自采手写测试集（小程序画板分布）。
- 预处理与训练数据保持一致：反色、去边框、按外接框缩放至 20×20 并居中到 28×28。
- 数据增强：随机旋转 ±10°、平移 ±10%、缩放 0.9–1.1。
- W3 起持续采集样本；W6 留整周调优，目标 ≥ 90%。

## 6. 部署视图

- 开发：本机分别启动 MySQL/Redis、模型服务（5001）、后端（8080）、前端（5173），Vite 代理 `/api` 至后端。
- 测试/演示：`docker compose up -d --build` 启动 5 个服务（mysql、redis、model-service、backend、frontend），前端 Nginx 反代 `/api`。
- 骨架阶段不启动 `model-worker`；W4 接入 Celery 训练后，在 `docker-compose.yml` 恢复该 worker 服务。
- 当前 Compose 持久化 MySQL、Redis；W1 离线训练输出到本地目录。模型服务的权重挂载与训练 worker 持久化在后续接入时配置。

## 7. 风险与备选

| 风险 | 备选 |
|---|---|
| Celery/Redis 环境不稳定 | `CELERY_TASK_ALWAYS_EAGER=1` 同进程执行训练（仅开发） |
| SSE 推送不稳定 | 前端 2s 轮询兜底（W5 实现） |
| 连续识别挤占工期 | W4 末评估，必要时降级为可选项 |
| 无 GPU 训练慢 | 默认 CPU + 小 epoch；演示用预训练模型 |

## 9. 现状补充（v1.1，2026-11-19）

> v1.0 描述的是 W1 骨架。本节补充 W2–W7 落地后的实际形态；**数据与存储细节见《05 详细设计 · 数据与存储》**。

### 9.1 模块现状

| 模块 | 实际职责 | 关键实现 |
|---|---|---|
| 业务网关（backend） | 鉴权与空间、识别与采集、数据集与版本、训练编排、模型注册与激活、平台状态 | Spring Boot 3 + JdbcTemplate + Flyway V1–V23 |
| 模型服务（model-service） | 单字/多位数推理、预处理、训练流水线、SVHN 与多位数裁字工具 | Flask + Waitress + PyTorch 2.5.1（CPU） |
| 训练执行（worker） | 消费 Celery 队列，按任务参数训练并回调后端 | Celery（`training` 队列，solo 池） |
| 管理端（frontend） | 识别、数据集、训练记录、参数可视化、模型管理、平台状态 | Vue 3 + Vite + ECharts |
| 小程序 | 画板识别与结果展示 | 微信小程序 |

### 9.2 关键流程（现行）

**数据集导入**
```
用户选目录 / 传 zip
  → 后端识别格式（folder / csv / filename / bbox）
  → 试运行：数量、标签分布、跳过原因、抽样自检
  → 确认：逐张校验 + 去重 + 落盘（内容寻址）
  → 写 t_collected_sample（source=IMPORT, source_dataset_id=本集, import_batch_id=批次）
```

**版本快照**
```
选来源（本数据集样本 / 指定版本合并）
  → 按 split_rule 划分 TRAIN/VAL/TEST（默认按样本随机）
  → 写 t_v2_dataset_version + t_v2_dataset_sample（标签、writer_key 固定）
  → 版本不可变，改动即新建版本
```

**训练**
```
参数可视化第②步 → POST /admin/training/tasks
  → 后端固化参数并导出 training-data/v<id>/
  → Celery 入队 → worker 训练（每轮回调指标）
  → 早停（画板模拟准确率连续 patience 轮无提升）
  → 产物登记 t_v2_model（origin=TRAINED/FINE_TUNED），可一键激活
```

**删除与清理**
```
删样本 → 删版本关联 → 引用为 0 时删记录与文件
删版本 → 有训练任务引用则拒绝（409）
删数据集 → 版本与批次一并删；归入样本恢复无归属；导入样本按引用计数删
后台 → 启动 60 秒后 + 每 6 小时清理孤儿文件（保护 30 分钟内新文件）
```

### 9.5 与 v1.0 的差异

| 项 | v1.0 | 现状 |
|---|---|---|
| 数据集 | 单表 `t_dataset` | 数据集 + 版本 + 版本内样本三表，版本不可变 |
| 样本 | 无统一采集池 | `t_collected_sample` 统一池，按数据集归属 |
| 导入 | 仅 MNIST 内置 | 六种形态（folder/csv/filename/zip/bbox/IDX 待做） |
| 训练 | 固定参数、无早停 | 参数可视化提交、逐轮 + step 指标、日志流、早停 |
| 权限 | ADMIN/USER | 增加 `platform_role` 与空间角色 |
| 部署 | 仅本机脚本 | 同左，Compose/Linux 待做 |
