## 2. 每一项解决的问题与实测证据

### P1-7 评估指标

- **问题**：训练产物只有三域总准确率，看不出"哪一类错得多""错的是哪些样本"。
- **做法**：`train_canvas_aug.py` 增加 `detailed_metrics()`：混淆矩阵、每类 P/R/F1、宏/加权平均、
  按置信度排序的前 20 个错误样本并拼成 `errors-<domain>.png`；前端 `TrainingMatrix.vue` 增加域切换与错误回溯列表。
- **证据**：训练产物 `metrics.detailed.{raw_mnist,canvas_simulated,photo_simulated}` 三域齐全；
  训练测试套件 **50** 项通过；前端矩阵组件测试通过。

### P1-8 模型对比

- **问题**：只能看单个版本的指标，无法回答"新版本到底比旧的强在哪"。
- **做法**：后端 `ModelCompareService/Controller`（`POST /admin/models/compare`，SUPER_ADMIN）
  在同一批样本上跑两个版本，返回并排指标 + 逐样本差异（谁对谁错）；模型服务新增 `/internal/v2/compare`。
- **证据**：`ModelCompareLabelTest` 覆盖标签为 VARCHAR 的坑（原实现 `(Number) row.get("label")` 会抛 ClassCastException）；
  端到端对比返回两边指标与差异样本。

### P1-9 标签映射与裁字可视化

- **问题**：CSV 表头只认英文关键字，猜不中就"可导入 0 张"；多位数图只说一句"建议裁成单字"。
- **做法**：预览返回 `csv{columns, matched}`，前端两个下拉手动映射（显式选列找不到时**不回落猜测**，
  提交时 `400 CSV_COLUMNS_UNMAPPED`）；多位数图返回 `cutSamples`（缩略图 + 相对比例段）。
  自检 `maxDigits` 2 → 4，修掉三位数静默漏检。
- **证据**：`colA,colB` → 提示手选；映射后 10/10；中文表头 `文件名,标签` 自动匹配；
  多位数 **3/3 检出**（改前 3 位漏检），`128 → 1[0.00-0.09] 2[0.38-0.61] 8[0.76-1.00]`。

### P1-10 导入异步化

- **问题**：大 zip 同步等待，1500 张 40–60 秒，2 万张必然超时且无法看到进度、无法中止。
- **做法**：V22 任务表 + 后端线程池执行器；`POST/GET/POST cancel` 三个接口；进度每 25 张落库，
  取消标记 1 秒缓存；ZIP/UPLOAD 临时目录在 `finally` 清理；批次回滚仍走原接口。
- **证据**：10 张目录 → `SUCCEEDED`；1350 张跑到 50 张时取消 → `CANCELED`，`imported=98`，
  `progress_done=108/1350`（**修复了"取消后进度跳 100%"的自造 bug**），批次可回滚；
  zip 异步导入后临时目录实测已删除；非法来源 `400`、任务不存在 `404`。

### P1-11 训练实时推送

- **问题**：训练监控每 2 秒轮询；训练记录页即便 SSE 已连通也照样轮询。
- **做法**：`live.js` 统一"只有 SSE 连上才停轮询"的判定；两个页面接入；日志仍按需拉取（SSE 不推日志）。
- **证据**：换票据 → `ready`；提交任务收到 `QUEUED → RUNNING → RUNNING → SUCCEEDED`；
  票据单次有效（200/401）；无票据 401。

### P1-12 保留旧划分

- **问题**：改比例或合并别的数据集后重建版本，训练/验证/测试归属整体洗牌，指标不可跨版本比较。
- **做法**：`BuildCommand.preserveSplitFrom` + V23 记录来源；来源必须是同一数据集 `READY` 版本。
- **证据**：沿用 v1、比例改 30/30 → **1200/1200 条划分不变**；不沿用同样 30/30 → **599 条变化**；
  跨数据集来源 `400 SPLIT_SOURCE_INVALID`。

## 5. 遗留与建议（P2 方向）

1. **多实例化**：导入任务与 SSE 广播都需要外部队列 / Redis Pub/Sub，当前是单实例假设。
2. **权重与模型的根因修复**：数据库基线与 Release 的 `registry.json` 仍靠脚本保证一致，
   建议加一条校验（启动时比对 DB 生效版本的 sha256 与 registry），不一致直接告警而不是等识别报 400。
3. **导入断点续传**：取消后只能重导（靠去重兜底）。
4. **前端 dev server 在 Windows 上的 watcher EBUSY**：改 `src/` 时偶发崩溃，需重启（已进部署手册故障表）。
