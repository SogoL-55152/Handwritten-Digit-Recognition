# 门牌数据集：检测与切分（test.tar.gz）

> 2026-11-18。`test.tar.gz`（13068 张门牌/街景数字照片）不是手写数字集：多数是 2–3 位印刷体数字，
> 无标签文件。本文记录我们在这个包上做的"先找数字、再切分"，以及全量实测结果。

## 1. 数据集事实

| 项 | 值 |
|---|---|
| 图片数 | 13068 张 PNG |
| 命名 | `0001.png … 13069.png`（序号，无标签） |
| 内容 | 街景门牌：砖墙、招牌、门上 1–3 位数字 |
| 尺寸 | 不等，约 40×20 到 240×96 |
| 标签 | **有**：	est/digitStruct.mat（SVHN 格式，含框与标签） |

## 2. 为什么原来的多位识别不行

线上多位识别假设"画布上只有数字"：垂直投影切分 + 逐字 28×28。门牌照片里有墙面、门框、招牌边框，
投影会把背景当成笔画：

- 切出一堆无意义片段 → `DIGIT_LIMIT`
- 两个数字黏成一段 → 只切出 1 段，被当成单个数字
- 数字占画面比例小 → 单字判据（过小/过宽）直接拒

## 3. 这次补的两步

**① 定位（`model-service/services/digit_detect.py`）**

把图片缩到 160px 宽，按亮度取最大连通区块（亮区 = 招牌、暗区 = 深色门牌），映射回原尺寸并留边。
不依赖 scipy（用 BFS 自己找连通域），单图约几毫秒。

**② 切分过滤**

投影切分后按"片段之间"的相对高度过滤：只保留高度 ≥ 最高片段 55% 的片段，丢掉过窄/过宽的噪声。
如果过滤把片段清空，退回原图未过滤结果，保证不比改造前更差。

三个候选（原图、亮区、暗区）都会跑一遍，按"片段数是否落在 1..maxDigits"打分，取最好的一组。

调用方式：`POST /internal/v2/predict/multi?detect=1`（默认关闭，不影响现有行为）。

## 4. 全量实测（13068 张，模型 `w4-task-8-a1`，maxDigits=3）

| 指标 | 原点切分 | 检测后切分 |
|---|---|---|
| 接受率 | 21.25%（2777 张） | **36.06%（4712 张）** |
| DIGIT_LIMIT（切出超上限） | 2941 | **405**（-86%） |
| 低置信度 | 7350 | 7951 |
| 1 位结果 | 1610 | 2737 |
| 2 位结果 | 783 | **1460** |
| 3 位结果 | 384 | **515** |
| 单字置信度均值 | 0.9838 | 0.9870 |
| 耗时 | — | 全量双口径 233.6 秒 |

**怎么解读：**

- 接受率翻到 1.7 倍，主要来自"不再被背景撑爆片段数"（DIGIT_LIMIT 掉了 86%）；
- 两位数结果从 783 涨到 1460，说明"两个数字黏成一段"的情况有改善；
- 低置信度仍是最大头（7951），这是**模型域差异**：它是手写数字训练出来的，对印刷体门牌的字体不熟；
- 正确率评测（用 digitStruct.mat）见 [SVHN-评测与可用性](SVHN-评测与可用性.md)：
  detect 的全体完全正确率 4.23%，oracle（给定框）11.62%。

```powershell
cd model-service
python -I tools/scene_eval.py --images D:/Temp/hdr-scene/test --limit 13068 --out D:/Temp/scene-report-full.json
```

脚本在进程内直接跑推理（不走 HTTP），两种口径同一批图对比，输出 JSON 报告。

## 6. 结论与下一步

- ①②已经让"门牌类照片"从基本不可用（21%）变到可用一半（36%），且没有改变手写画板的现有行为；
- 想继续提升，收益最大的是**切分出更多正确片段**（目前 7951 张是低置信度，说明片段仍不干净）；
- 想量化"准确率"，必须补标签（人工核对 200–500 张即可建评测集）；
- 这个包是**印刷体**，不要指望它直接提升手写准确率；手写提升要靠采集真实手写样本。
