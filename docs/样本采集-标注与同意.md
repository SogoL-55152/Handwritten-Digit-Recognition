# 样本采集：用户标注与同意

> 2026-11-12。识别页新增「你写的是几？」——用户自己给出正确答案，**勾选同意后**才保存这张图。
> 这是 W6 自采数据的产品化入口，也是目前唯一能持续拿到"真实用户笔迹 + 正确标签"的通道。

## 1. 为什么由用户标注

模型预测不能当标签：它会错，而且错得自信（曾把 9 判成 7，置信度 0.976）。只有用户自己点的数字才是可信标签。分成两种记录：

| 场景 | label | predictedDigit | 价值 |
|---|---|---|---|
| 用户确认模型判断 | 与实际一致 | 同 label | 高质量正例、难例分布 |
| 用户纠正模型 | 实际数字 | 模型的错误答案 | **最有价值的错误样本** |
| 识别被拒（422） | 实际数字 | 空 | 当前拒识策略的漏判/误拒分析 |

## 2. 接口

```
POST /api/v2/workspaces/{workspaceId}/collected-samples   (multipart/form-data)
  image            PNG/JPEG，≤5 MiB，最长边 ≤2048（复用现有图片校验）
  label            0–9
  consent          true（false 一律 400 CONSENT_REQUIRED）
  predictedDigit   可选，本次模型预测
  confidence       可选，0–1
  modelVersion     可选
  recognitionId    可选，关联的识别记录
  source           默认 WEB
```

响应：

```json
{"code":0,"data":{"id":"1","duplicate":false,"contributedTotal":3}}
```

- **重复提交不新增**：同一 `workspace + user + 图片摘要` 已存在时返回 `duplicate=true`，不写第二份文件。
- 限流：每人每分钟 60 次（复用 `RateLimiter`）。
- 另有一个只读接口 `GET /workspaces/{id}/collected-samples/summary`，只返回**本人**贡献数（`total`、`labels`），不暴露他人内容。

### 2.1 多位数样本：用户手输整串

多位数识别结果下方有一个输入框「你写的是什么？」，用户**自己输入**实际写的数字串（1–4 位），不是点选：

| 字段 | 值 |
|---|---|
| `labelText` | 用户输入，如 `351`（必须匹配 `^[0-9]{1,4}$`） |
| `predictedText` | 模型给出的整串（用于对照） |
| `label` | **不传**（与 `labelText` 二选一，同时传返回 400） |
| `recognitionId` | 关联这次多位数识别记录 |

与单字采集共用同一个端点 `POST /workspaces/{id}/collected-samples`，靠 `sample_kind` 区分：

- `SINGLE`：`label` 0–9，`label_text` 为空
- `MULTI`：`label` 为空，`label_text` = 整串，`digit_count` = 位数

同意开关与单字共用（左侧那个，勾一次长期有效）。

## 3. 存储与隐私

| 项 | 做法 |
|---|---|
| 目录 | `hdr.collected.dir`（环境变量 `HDR_COLLECTED_DIR`），默认仓库根下 `collected-samples/` |
| 路径 | `<root>/<workspaceId>/<yyyyMM>/<sha256>.png`，写入前校验路径不逃逸出根目录 |
| 数据库 | `t_collected_sample`：标签（单字 `label` / 整串 `label_text`）、预测、置信度、模型版本、摘要、相对路径、大小、同意标记 |
| 同意 | 表上有 `CHECK (consent = 1)`，未同意的样本在数据库层面就写不进去 |
| 隔离 | 只有本人能看到自己的贡献统计；没有跨用户列表接口 |
| 删除 | 按 `creator_id` 删除行 + 对应文件即可；删除流程尚未做成接口（见限制） |

`.gitignore` 已忽略 `collected-samples/`，采集数据不会进仓库。

## 4. 数据结构

```sql
CREATE TABLE t_collected_sample (
  id, workspace_id, creator_id, recognition_id,
  label TINYINT, predicted_digit TINYINT, confidence DOUBLE, model_version,
  source, image_digest CHAR(64), artifact_path, size_bytes, content_type,
  consent TINYINT(1), created_at,
  UNIQUE KEY uk_collected_digest (workspace_id, creator_id, image_digest)
)
```

## 5. 怎么变成评测集

采集到的行可以直接转成 `evaluate_samples.py` 需要的 manifest（`origin` 记为 `actual-user-board`，`writerId` 用 `creator_id`）：

```sql
SELECT id, artifact_path, label, creator_id
FROM t_collected_sample
WHERE consent = 1 AND label BETWEEN 0 AND 9
ORDER BY id;
```

按 `artifact_path` 复制/软链到同一目录，生成：

```json
{"samples":[{"id":"1","file":"<sha>.png","label":7,"origin":"actual-user-board",
  "writerId":"3","captureSessionId":"collected-202611","consent":true}]}
```

注意：`writerId` 必须用于**按人分折**，同一 `creator_id` 的样本不能既训练又评测。

## 6. 前端

### 6.1 同意开关（左侧，按钮下方）

识别页左侧「识别数字 / 清空画板」按钮**下方**有一个同意勾选：

> 同意把识别图片与我的标注用于模型评估与改进（勾选一次后长期有效，可随时取消）

- 勾选状态存 `localStorage`（键 `hdr.consent.v1`），**一次勾选后一直生效**，刷新/重开页面仍在；
- 取消勾选立即失效，之后提交会被服务端拒绝（400 `CONSENT_REQUIRED`）；
- 注意：这是**浏览器维度**的记忆，同一台设备换账号仍沿用。共用设备时应手动取消。

### 6.2 正误确认（右侧，预测数字下方）

识别结果出来后，右侧「预测数字 X」下方直接出现确认入口：

| 情况 | 交互 |
|---|---|
| 模型对了 | 点「✓ 对，就是 X」→ 一步提交，标签 = X |
| 模型错了 | 点「✗ 不对，实际是…」→ 展开 0–9 → 点正确的数字 → 直接提交 |
| 识别被拒（422，无结果） | 右侧直接显示「这次没有给出结果。你实际写的是几？」+ 0–9 |
| 不想标 | 点「跳过这次标注」 |

提交成功后按钮收起，显示「已收录，感谢！你已贡献 N 条」；重复图片显示「这张图片之前已经采集过」。
每次重新识别都会重置该区域，不会把上一张的标签带到新图。

**没勾同意就点确认**时，右侧会提示「请先在左侧勾选同意，才会保存这张图」，不会静默失败。

## 8. 已知限制

- 没有"删除我的样本"接口，只能由维护者按 `creator_id` 删除；隐私要求高的话需要补。
- 没有审核环节：恶意/错误标注会直接进库，转测评集前应抽样人工核对。
- 图片存本地磁盘，没有冷热分层与容量配额（W8 之后才考虑）。
- 小程序端尚未接入该面板，目前只有 PC 网页。

## 9. 多位数样本的数据结构（V12 + V13）

```sql
ALTER TABLE t_collected_sample
  ADD COLUMN sample_kind  VARCHAR(8) NOT NULL DEFAULT 'SINGLE',
  ADD COLUMN label_text   VARCHAR(8) DEFAULT NULL,
  ADD COLUMN predicted_text VARCHAR(8) DEFAULT NULL,
  ADD COLUMN digit_count  TINYINT DEFAULT NULL;

ALTER TABLE t_collected_sample MODIFY COLUMN label TINYINT DEFAULT NULL;  -- V13：多位数不需要单字标签
```

`label` 的 `CHECK (label BETWEEN 0 AND 9)` 对 NULL 求值为 UNKNOWN，MySQL 视为通过，所以不用改约束。
