# 基础体验版：范围与发布清单

面向项目维护者和受邀体验成员。当前目标是小范围试用，不是正式公开发行。代码可在资源准备前验证；可分享的网址/微信体验码仍需要真实服务器、HTTPS域名和有权使用的小程序账号。

## 体验功能

双端账号注册/登录、默认个人空间、单个0–9手写识别、清空、数字/置信度/耗时和折叠详情、修改密码、退出、帮助/隐私说明。小程序可直接注册，不再依赖PC预注册。

不开放在线训练、团队管理、相册/拍照、多数字、收费或完整历史CRUD。开发模式保留原W2入口；界面隐藏不替代后端成员权限。

## 配置与本地查看

- 后端：`SPRING_PROFILES_ACTIVE=pilot`。关闭旧认证/bootstrap/Swagger和默认跨域；只允许注册时创建个人空间。`PILOT_REGISTRATION_CODE`仅服务端，16–256字符，空值关闭新增注册；维护者线下提供给体验成员。不要在VITE或小程序包中嵌入。
- 网页：`VITE_APP_MODE=pilot`。公开字段为 `VITE_PILOT_OPERATOR`、`VITE_PILOT_CONTACT`、`VITE_PILOT_PRIVACY_VERSION`；本地dev可缺失但显示未配置，pilot构建缺项拒绝。这些是构建时变量。
- 小程序：开发配置见 `miniprogram/config/public.js`。trial/release只允许真实配置的HTTPS origin，未知环境/缺失/开发地址即禁止网络；地址改变清除旧候选会话。源码AppID不代表本项目发布资格，不能未经确认上传。
- 缺少真实联系人等时，可以用清楚标记为“本地测试”的字段做本地测试，不可把它当可分享配置。

改密接口 `POST /api/v2/auth/password` 成功后撤销所有会话。原密码错误不退出；每账号5次/15分钟（失败也计数），超时不自动重发。密码找回及账号删除通过帮助页联系维护者，先核验本人，不能只凭用户名重置；退出不等于删除。

## 小程序候选包工具

Node22，配置JSON仅允许公开字段（不要放密码或注册码）：

```json
{
  "apiBaseUrl": "填写实际HTTPS地址",
  "operator": "填写实际主体",
  "contact": "填写实际联系方式",
  "privacyVersion": "填写实际版本",
  "appid": "填写有权使用的AppID"
}
```

```text
node scripts/pilot-release.mjs check --config <本地公开配置.json>
node scripts/pilot-release.mjs package-miniprogram --config <本地公开配置.json> --name <版本名> --confirm-appid-authorized
```

缺配置/占位值检查失败是预期行为。授权确认参数必须由操作者在确有权限时提供；工具只核验格式，不能证明所有权。工具仅生成新的 `dist/pilot-miniprogram-<版本名>`，拒绝覆盖现有目录；白名单包含运行所需页面/组件/工具，排除开发原型、测试、私有配置等，生成 `urlCheck=true` 的配置。不执行微信上传，不生成微信体验二维码，不代表隐私/资质审核通过。

## 服务器部署准备（未实际公网执行）

1. 选择支持Docker的单台服务器及有权使用的域名，按所在地/平台要求落实备案、证书和微信账号资格；不要假定测试号可以正式发布。
2. 使用新专用数据库/独立Compose项目名，不能将pilot直接指向用户旧库。W1升级仍按后端指南先备份和验证。
3. 用根环境模板及 `deploy/pilot/.env.example` 准备本地私有环境文件、独立密钥与可信权重绝对路径。不要提交env/证书/备份/权重。
4. 在具备Docker且获准拉取/构建的环境执行：

   ```text
   docker compose --env-file <私有env> -p hdr-pilot -f docker-compose.yml -f docker-compose.pilot.yml config --quiet
   docker compose --env-file <私有env> -p hdr-pilot -f docker-compose.yml -f docker-compose.pilot.yml up --build -d
   ```

   配置校验用 `--quiet`，避免将展开后的密钥输出到终端/日志。当前没有运行Docker，静态YAML检查不等于容器启动验证。
5. 网页仅映射127.0.0.1:8088；Java/Python/MySQL不发布主机端口。资源预算合计约3GiB内存，另需操作系统空间，建议至少4GiB内存/2核的试用主机；实际资源需测量，非容量承诺。
6. 使用 `deploy/pilot/nginx-https.conf.template` 在主机配置唯一TLS入口：替换真实域名/证书路径，证书权限受控；外部只能访问HTTPS网页/API，HTTP重定向。不开Python/DB公网端口。模板不会自动部署或申请证书。
7. 网页同源调用Java；小程序配置同一HTTPS域名的request/uploadFile合法域名。试用不依赖关闭域名校验。服务器不信任客户端转发IP，代理后的IP限流共享，账号/空间限流独立。默认识别10次/分钟/用户及空间，未启用日配额账本。
8. 用受控账号核验身份/识别和运营health-summary：MySQL、模型确实UP；静态 `/api/health` 仅表示进程存活。模型容器healthcheck包含真实可信权重readiness；Docker的unhealthy不自动代表已重启，维护者需监控和处理。

## 数据与人工维护

- 图片仅作当次推理，不永久保存原图、不用于训练；识别元数据/摘要仍保存。临时上传文件、访问/错误日志和备份须另行核查。
- 参考保留：识别元数据30天，日志7天，滚动备份7天；这些不是后台自动清理承诺。分享前运营者必须落实并确认对外说明。
- Compose按大小轮转日志（每容器最多3×10MiB），不等于7天删除；管理员另按时间清理。禁止在HTTP日志记录Authorization、请求正文或注册码。
- 备份使用MySQL官方dump的受控选项文件，不将密码放命令行；文件目录只允许运维账号访问。恢复到另一个新空库，核对Flyway、用户/空间/记录数量及一次识别后才切换。保留W1→W2恢复流程。
- 过期会话/识别记录维护工具为 `scripts/pilot-maintenance.py`，只接受 `hdr_pilot_*` 库，默认预览；例如：

  ```text
  python -I scripts/pilot-maintenance.py --mysql <可信mysql客户端绝对路径> --defaults-file <私有客户端配置绝对路径> --database hdr_pilot_app --days 30 --batch 500
  ```

  核验备份和预览后追加 `--apply --confirm-database hdr_pilot_app --backup-verified` 才删除单批。工具不删除账号/进行中记录/文件/日志/备份，不自动循环、不在启动时清库。其SQL安全测试已执行，但尚未在实际pilot库执行清理；不要将预览工具当作已实施留存。删除识别元数据将影响现有“累计记录数”用量，界面不是永久审计账本。
- 找回/删除人工流程：确认请求来源和本人身份，停止该账号写入、撤销会话、备份受控记录，再核对关联空间/成员/记录。涉及其他成员或私有资产时暂停删除并人工处理，不盲目级联。支持渠道/处置时限必须填写真实信息，不能声称已具备自动找回/注销。
- 结束试用或发生泄露：清空服务端注册码关闭新注册；按情况撤销会话/轮换JWT及内部token，同步Java/Python配置；旧会话失效是预期。部署回滚前先判断迁移兼容性，不让旧应用向新schema盲写。

- [ ] 发布范围/测试证据/已知限制说明清楚；提交/推送、微信上传及公网部署另行授权。
