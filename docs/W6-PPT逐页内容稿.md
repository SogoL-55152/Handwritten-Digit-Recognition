## P4 功能一：模型管理

- **标题**：多个模型并存，一键切换
- **结论条**：切换后新请求立即用新模型，旧结果可追溯
- **用户能做什么**（4 条）：
  - 查看全部模型：版本、预处理版本、大小、状态
  - 启用/停用任意已注册模型
  - 一键把某个模型设为当前生效
  - 每次识别记录都写明用了哪个模型版本
- **验证**：W3 联调 18 项（含切换后识别、非法模型被拒、停用后不可用）
- **技术（一句）**：模型注册表 + 文件摘要校验 + 运行中热加载
- **讲稿**（50 秒）：
  以前只有一个固定模型，现在可以并存多个，页面上一键切换，切换后新的识别请求立刻用新模型。每条识别记录都会写明版本，方便回溯是哪次切换后出的问题。
- **版面**：左功能列表，右截图位（模型管理页）。

## P5 功能二：训练任务管理

- **标题**：页面上建任务，后台自己排队
- **结论条**：任务崩了会自动重投，不用人工盯着
- **用户能做什么**（4 条）：
  - 在页面配置数据集、轮数、样本量、学习率，选「从头训练」或「基于已有模型微调」
  - 提交后进入排队，状态可见：排队 / 运行 / 成功 / 失败
  - 失败能看到失败原因，不会静默丢失
  - 训练完的模型自动进入模型管理，可直接切换使用
- **验证**：W4 联调 11 项，其中「worker 被强制中断后任务在第 2 次尝试完成」
- **技术（一句）**：Redis + Celery 队列，租约心跳检测，失联任务自动重投
- **讲稿**（50 秒）：
  训练任务全部在页面上配置和提交，后台排队执行。比较关键的是容错：我们专门测了把 worker 杀掉的情况，任务会在第二次尝试自动完成，不需要人工干预。
- **版面**：左功能列表，右截图位（训练任务页 + 状态标签）。

## P6 功能三：训练可视化与统计

- **标题**：训练过程实时看，使用情况有数
- **结论条**：曲线逐轮刷新；统计页能看到调用量、拒识、模型分布
- **用户能做什么**（4 条）：
  - 点任务的「曲线」，在任务行下方展开逐轮损失与准确率
  - 训练中曲线自动刷新，不用手动刷新页面
  - 统计页看：调用总量、返回结果、拒识、服务失败、平均耗时
  - 看日趋势、模型使用分布、最近识别明细
- **验证**：W5 联调 13 项（含实时推送、断线重连、统计口径）
- **技术（一句）**：SSE 实时推送；用一次性票据解决浏览器无法带鉴权头的问题
- **讲稿**（50 秒）：
  训练曲线是实时推的，训练中会自己刷新。统计页把调用量、拒识、失败分开统计，避免把"模型跑完了但结果不确定"算成有效结果。

## P7 功能四：多位数识别

- **标题**：从「识别一个数字」到「识别一串数字」
- **结论条**：画板或拍照写 1–4 位数字，返回整串和逐位置信度
- **用户能做什么**（5 条）：
  - 画板写多位数字（数字之间留空隙），点「识别多位数字」
  - 拍照/选图后同样可以识别多位数，照片会先自动处理
  - 结果给出整串（如 351）和每一位的置信度
  - 置信度低于 90% 的位会标红，提示重写
  - 结果写入识别历史，可在统计页回看
- **数据**（小表格，照抄）：

| 位数 | 整串正确率 | 切分正确率 |
|---|---|---|
| 1 位 | 97.5% | 100% |
| 2 位 | 91.7% | 99.2% |
| 3 位 | 86.7% | 100% |
| 4 位 | 85.8% | 100% |

- **技术（一句）**：按列投影切分，逐段复用原有单字模型，没有重新训练
- **讲稿**（60 秒）：
  多位数是本周最大的功能。切分几乎不丢分，1 到 4 位都是 99% 到 100%；真正影响整串的是逐位准确率 95.5%。所以 3 位整串现在是 86.7%，离 90% 差一个点，靠微调可以补。
- **版面**：左功能列表，右下数据表；3 位那行用强调色。

## P8 功能五：用户标注与样本采集

- **标题**：让用户告诉我们对不对
- **结论条**：用户标对错 → 数据回流 → 用于改进模型
- **用户能做什么**（4 条）：
  - 单字识别后点「✓ 对」或「✗ 不对」再点正确数字
  - 多位数识别后点「✓ 对，就是 351」，或「✗ 不对，我来输入」手输正确串
  - 同意开关勾一次长期有效，可随时取消
  - 未同意不保存；同一张图不会重复入库
- **为什么重要**（2 条）：
  - 模型预测不能当标签——曾把 9 判成 7，置信度 0.976
  - 采集时同时记录模型当时的判断，能直接区分「模型对 / 模型错」
- **数据**：本周采集 **38** 条（其中多位数 10 条）
- **技术（一句）**：图片按摘要去重落盘；同意在数据库层面强制校验
- **讲稿**（50 秒）：
  模型会错，而且错得自信，所以标签必须由用户给。我们做了单字点选、整串确认、整串手输三种方式，采集时同时存下模型当时的判断，这样后面能直接拿错误样本做改进。
- **版面**：左功能列表，右两张小截图（单字判断 / 多位数输入）。

## P9 功能六：照片预处理与识别详情

- **标题**：照片先“洗干净”，结果能回看
- **结论条**：照片识别从对 3/6 提到对 5/6；每条结果都能看原图
- **用户能做什么**（4 条）：
  - 导入照片后点「查看预处理效果」，看到白底黑字、笔画加粗后的图
  - 这张处理后的图就是实际送进模型的输入
  - 统计页「我的最近识别」每行点「查看」，弹出原图 + 结果、状态、模型版本、请求 ID
  - 只有本人能看自己的原图
- **数据**（小表格）：

| 指标 | 处理前 | 处理后 |
|---|---|---|
| 识别正确 | 3/6 | **5/6** |
| 被接受 | 2/6 | **5/6** |

- **技术（一句）**：光照归一化 + 自动阈值二值化 + 形态学加粗；原图按摘要落盘
- **讲稿**（50 秒）：
  真实照片有阴影和纸纹，直接送模型会把阴影当笔画。我们加了预处理，六张实拍照片从对 3 张提到对 5 张。同时每条识别都能回看原图和当时的模型版本，方便排障和验收。
- **版面**：左功能列表，右「处理前/处理后」对比图。

## 制作规范

### 全局

- 比例 **16:9**，共 **10 页**，汇报 **8–10 分钟**
- 每页文字上限：**1 个标题 + 1 个结论条 + ≤6 条要点**（表格不算要点）
- 标题 ≥ 32pt，正文 ≥ 18pt，表格 ≥ 14pt
- 配色：深蓝主色 + 灰底；状态色仅用绿（✅）/ 黄（🟡 未完成）/ 红（❌）/ 橙（强调）
- 百分比统一一位小数（如 86.7%）

### 禁止

- 不要写"每个人各自做了什么"
- 不要出现没有来源的数字
- 不要把 1/2/3/4 位准确率合并成一个平均数
- 不要写"准确率已达标"——本周是 86.7%

### 数字来源（若被问）

- 多位数分位准确率：20,074 条真实触屏笔迹合成串，每档 120 组
- 照片前后对比：6 张实拍照片，同一模型、同一阈值
- 采集条数：数据库实时计数（识别 326 条、采集 38 条）
- 单测：后端 156 / 模型 233 / 前端 248 / 小程序 435
