# 手写数字识别系统 — 需求规格说明书 v1.0

> 编制：M1　|　日期：2026-10-24　|　状态：待团队评审确认（周四前完成）

## 1. 项目目标

构建一套手写数字识别系统：用户在手机端画板书写数字，后端调用深度学习模型返回识别结果；PC 管理端提供模型训练、模型管理、用户管理与统计分析能力。核心验收指标为**真实手写场景下识别准确率 ≥ 90%**。

## 2. 用户与角色

| 角色 | 使用端 | 能力 |
|---|---|---|
| 普通用户 | 微信小程序 | 注册/登录、单字与连续手写识别、查看识别记录 |
| 管理员 | PC 管理端 | 用户管理、数据集管理、发起训练、模型管理与切换、查看统计 |

## 3. 功能需求

### FR-1 手写识别（小程序）

- FR-1.1 提供画板，支持触摸书写、清空。
- FR-1.2 点击识别后上传画板图像，返回识别数字与置信度。
- FR-1.3 增强项：支持连续多位数字识别（W5，允许降级）。

### FR-2 模型训练管理（PC）

- FR-2.1 选择数据集（MNIST / 自采扩展数据集）。
- FR-2.2 配置超参数：训练轮数、批大小、学习率、模型名称。
- FR-2.3 发起训练后异步执行，页面实时展示损失、准确率、进度。
- FR-2.4 训练完成后模型自动登记，可在模型管理中启用。

### FR-3 模型管理（PC）

- FR-3.1 展示模型列表：名称、版本、准确率、状态、创建时间。
- FR-3.2 同一时刻仅一个模型为活跃状态。
- FR-3.3 支持一键切换活跃模型；活跃模型不可删除。

### FR-4 用户管理（PC）

- FR-4.1 用户注册、登录，JWT 鉴权。
- FR-4.2 管理员分页查询用户、启用/停用账号。
- FR-4.3 角色区分：`ADMIN`、`USER`。

### FR-5 统计分析（PC）

- FR-5.1 概览：用户数、模型数、调用量、平均准确率、当前活跃模型。
- FR-5.2 近 7 天调用趋势。
- FR-5.3 模型使用分布。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 | 识别接口 P95 响应时间 ≤ 500 ms（不含网络与首次模型加载） |
| NFR-2 | 训练任务异步执行，不阻塞 Web 请求；服务重启后任务状态可恢复（Redis） |
| NFR-3 | 鉴权：除登录/注册/健康检查外，接口均需 JWT |
| NFR-4 | 上传图片 ≤ 5 MB，仅接受常见图片格式 |
| NFR-5 | 数据库表使用逻辑删除；密码 BCrypt 存储 |
| NFR-6 | 支持 Docker Compose 一键部署 |

## 5. 验收口径

1. 小程序开发版/体验版完成"书写 → 识别"闭环。
2. 使用自采手写测试集评估，准确率 ≥ 90%，并输出评估报告。
3. 管理端完成训练任务全流程演示，训练曲线实时更新。
4. 至少两个模型可切换，切换后识别请求使用新模型。
5. 交付文档齐全（见根目录 README）。

## 6. 本期不做

- 正式发布小程序（受备案/审核周期限制）。
- 多租户、计费等商业化能力。
- 除数字（0–9）外的字符识别。
