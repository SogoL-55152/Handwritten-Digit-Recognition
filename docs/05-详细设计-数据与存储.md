| 项 | 值 |

## 1. 范围与命名约定

- 只描述**库、文件、Redis** 三处持久化，不含接口与页面（见 `05-详细设计-服务与接口`、`05-详细设计-前端页面`）。
- `t_v2_*` 为现行表；无前缀的 `t_dataset` / `t_model` / `t_train_task` / `t_recognition_log` 是 W1 遗留，**不要在新代码里使用**。
- 所有时间列：`datetime` 为本地时间（应用写入），`timestamp(3)` 为毫秒精度（默认值由库生成）。
- 计数列（`sample_count` / `train_samples`）是**冗余统计**，以关联表为准，改动后需要重算。

## 2. 存储分层

| 层 | 内容 | 位置 |
|---|---|---|
| MySQL | 账号、空间、识别记录、样本元数据、数据集版本、模型、训练任务与指标、导入批次 | 库 `hdr_w2_it_live`（测试）/ 生产库同结构 |
| 文件系统 | 采集样本原图（内容寻址）、识别原图、训练导出目录、模型权重 | `collected-samples/`、`recognition-images/`、`training-data/v<id>/`、`model-service/weights/` |
| Redis | Celery 队列、训练日志环形缓冲、worker 心跳、SSE 事件与票据 | 见第 7 节 |

**设计原则**：数据库只存**元数据与指针**，图片与权重落盘；删除时先删库记录，再按引用计数清文件（见第 6 节）。

## 3. 实体关系（逻辑）

```
t_user 1─* t_workspace（owner_id；个人空间由 personal_user_id 唯一约束保证 1:1）
t_user 1─* t_auth_session
t_user 1─* t_recognition_v2（按 workspace_id + creator_id 归属）
t_workspace 1─* t_workspace_member（联合主键 workspace_id + user_id）
t_workspace 1─* t_v2_dataset ─* t_v2_dataset_version ─* t_v2_dataset_sample
t_v2_dataset 1─* t_import_batch；t_v2_dataset_sample.sample_id → t_collected_sample.id

t_v2_model *─1 t_v2_training_task (target_model_id)
t_v2_training_task 1─* t_v2_training_metric (task_id, attempt)
t_v2_training_task *─1 t_v2_dataset_version (dataset_version_id, 可空)
```

### 4.7 框架表

## 5. 关键不变量与约束

| 不变量 | 实现 | 违反后果 |
|---|---|---|
| 同一数据集内同一张图不重复 | `uk_collected_digest(workspace_id, creator_id, image_digest, source_dataset_id)` | 重复导入被吞，不报错（`duplicates` 计数） |
| 同一 scope 只有一个生效模型 | `active_marker` 生成列 + `uq_v2_model_single_active(scope, active_marker)` | 切换生效模型是「先停用再启用」的事务 |
| 同一数据集版本号唯一 | `uk_dataset_version(dataset_id, version)` | 重复建版本直接报错 |
| 版本内样本唯一 | `uk_version_sample(version_id, sample_id)` | 同一批样本不能重复进同一版本 |
| 版本不可变 | 无 UPDATE 路径，只有建/删 | 改数据要新建版本 |
| 样本归属唯一 | `t_collected_sample.source_dataset_id` 单列 | 一张图同时只能属于一个数据集 |
| 训练任务参数可复现 | 参数落在任务行（epochs/samples/batch/lr/seed/photo_ratio/init_from） | 回放时不需要外部配置 |
| 每任务每尝试每轮指标唯一 | `uk_metric_task_attempt_epoch` | 重投后同轮次覆盖不会重复 |

## 6. 文件存储与孤儿清理

| 目录 | 存什么 | 命名 | 清理方式 |
|---|---|---|---|
| `collected-samples/` | 采集/导入的样本原图 | `<workspaceId>/<yyyyMM>/<sha256>.png` | 删除记录后按引用计数删文件；后台启动 60 秒后及每 6 小时扫一次 |
| `recognition-images/` | 识别原图 | 按摘要去重 | 随识别记录删除（暂不自动清理） |
| `training-data/v<id>/` | 版本导出给模型服务的 PNG | 按 split/label 分目录 | 训练任务删除时可清理（暂保留） |
| `model-service/weights/` | 模型权重与 `registry.json` | `<version>.pt` | 模型删除时同步清理 |

**孤儿判定**：`SELECT COUNT(*) FROM t_collected_sample WHERE artifact_path=?`，为 0 才删文件。
**保护期**：自动清理只处理修改时间超过 30 分钟的文件，避免删掉「刚写完、记录尚未提交」的图片。

## 11. 已知取舍

| 取舍 | 原因 | 后续选项 |
|---|---|---|
| 图片存文件系统、库里只存指针 | 避免大字段污染缓冲池 | 对象存储（MinIO/S3）需要抽象 `ArtifactStore` |
| 汇总 `metrics` JSON 与逐轮表并存 | 回放读 JSON 快，查询走表 | 数据量大后只留表 + 预聚合 |
| 版本不可变 | 保证可复现 | 需要「追加样本」时新建版本 |
| 去重按数据集 | 同一张图可用于不同数据集 | 全局去重需要换唯一键 |
| SSE 票据存进程内 | 单实例部署简单 | 多实例需 Redis Pub/Sub |
