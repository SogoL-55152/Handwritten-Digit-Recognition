## 4. 发现并修复的缺陷

### 4.1 空库引导管理员没有个人空间（已修复）

**现象**

- 用 `HDR_BOOTSTRAP_ADMIN_*` 创建管理员后登录成功
- 但登录返回 `defaultWorkspaceId=None`
- 后续请求（识别、新建数据集）全部 `400 VALIDATION`

**根因**

- `V2AdminBootstrap` 只创建 `SUPER_ADMIN` 用户，不创建个人空间
- 正常注册流程 `V2AuthService.register` 才会调用 `workspaces.createPersonal(...)`

**修复**

`V2AuthService.login` 在默认空间为空时补建个人空间：

```java
String defaultWorkspaceId = workspaces.defaultWorkspaceId(user.id());
if (defaultWorkspaceId == null) {
    // 空库引导管理员没有个人空间：首次登录时补建
    defaultWorkspaceId = workspaces.createPersonal(user.id(), user.username()).id();
}
return session(user.id(), user.safe(), defaultWorkspaceId);
```

**验证**：修复后登录返回 `默认空间=1`，冒烟 13/13 通过。提交信息：

```
fix(auth): 空库引导管理员首次登录时补建个人空间
```

## 5. 环境层面的问题（非代码缺陷）

| 问题 | 表现 | 处理 | 对真实用户的影响 |
|---|---|---|---|
| GitHub 直连被拦截 | `fetch-weights.ps1` 下载失败 | 复制现有权重完成验证 | 网络正常的用户直接执行脚本即可 |
| 克隆不含 MNIST | 训练报 `--data-dir must contain official MNIST IDX files` | 复制 MNIST 数据 | 训练前需执行 `scripts/fetch-mnist.py` |
| 复制的 registry 含历史任务号 | 训练报“版本已登记为其它产物（sha256 不一致）” | 清理为仅保留基线 `w4-task-8-a1` | 从 Release 拉取的新 registry 只有基线，不会冲突 |
