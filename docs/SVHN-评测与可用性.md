# SVHN：数据集可用性与正确率评测

> 2026-11-18。纠正前一版判断：`train.tar.gz` / `test.tar.gz` 里**有标签**，它们是 SVHN
> （Street View House Numbers）。之前只看前 25 个条目、只看到 PNG，误判为"无标签"。

## 1. 这是什么

| 文件 | 内容 | 图片数 | 标签 |
|---|---|---|---|
| `train.tar.gz` | `train/*.png` + `train/digitStruct.mat` | 33402 | 有（含框） |
| `test.tar.gz` | `test/*.png` + `test/digitStruct.mat` | 13068 | 有（含框） |

`digitStruct.mat` 是 MATLAB 7.3（HDF5）。每张图给出若干数字框（left/top/width/height）
与标签（label=10 表示数字 0）。位数分布：

| 位数 | 训练集 | 测试集 |
|---|---|---|
| 1 位 | 5137 | 2483 |
| 2 位 | 18130 | 8356 |
| 3 位 | 8691 | 2081 |
| 4 位 | 1434 | 146 |
| 5+ 位 | 10 | 2 |

所以**它能用来做真正的正确率评测**，也能用来训练检测器与微调模型。

## 2. 评测工具

`model-service/tools/svhn_eval.py`：读取 `digitStruct.mat`，按三种口径跑同一批图：

- `baseline`：整图直接多位识别（线上默认）
- `detect`：先 `digit_detect` 找数字区再切分（`detect=1`）
- `oracle`：用数据集给的框裁剪（**检测上限**，衡量"检测完美时能到多少"）

```powershell
cd model-service
python -I tools/svhn_eval.py --images D:/Temp/hdr-scene/test `
  --labels D:/Temp/hdr-svhn/test/digitStruct.mat --limit 13068 --out D:/Temp/svhn-report-full.json
```

## 3. 全量结果（13068 张，模型 `w4-task-8-a1`，maxDigits=3）

| 口径 | 接受率 | 接受内完全正确 | 全体完全正确 | 接受内逐位正确 |
|---|---|---|---|---|
| baseline | 21.25% | 14.37% | 3.05% | 29.81% |
| detect | **36.06%** | 11.74% | **4.23%** | 27.71% |
| oracle（给定框） | 37.61% | **30.91%** | **11.62%** | **53.46%** |

按位数（全体完全正确率）：

| 位数 | baseline | detect | oracle |
|---|---|---|---|
| 1 位（2483 张） | 8.8% | 12.2% | **35.1%** |
| 2 位（8356 张） | 1.9% | 2.7% | 7.3% |
| 3 位（2081 张） | 1.1% | 1.4% | 4.1% |

耗时：三种口径各跑一遍全量约 206 秒（进程内推理，不走 HTTP）。

## 4. 怎么解读

1. **检测确实有效**：接受率 21.25% → 36.06%，`DIGIT_LIMIT` 从 2941 降到 405。
2. **但检测不是全部**：接受内完全正确率反而略降（14.37% → 11.74%）——检测把更难的样本也捞了上来。
3. **真正的瓶颈是模型域差异**：即使给标准框（oracle），2 位数字只有 7.3% 完全正确、
   逐位才 53%。这是一个**手写数字模型**去认**印刷体街景数字**，字体、模糊、透视全都不在训练分布里。

## 5. 结论：能用，而且用法不止一种

| 用法 | 可行性 | 说明 |
|---|---|---|
| **正确率评测** | ✅ 已做 | 13068 张带标签，可当"真实场景"基准 |
| **检测器训练** | ✅ 可以 | 33402 张带框，可训练小检测器替代启发式定位 |
| **模型微调** | ✅ 最值得做 | 33402 张带标签，微调后预计大幅提升拍照场景准确率 |
| 提升手写准确率 | ❌ 不适用 | 印刷体 ≠ 手写，别指望它提升画板数字 |

## 6. 下一步建议

如果目标是"**拍照导入的准确率**"，按这个顺序做：

1. 用 `train.tar.gz` 的框把数字裁好，微调现有模型（1–2 轮，保持手写样本混训）；
2. 微调后用本工具在测试集上对比 `exactMatchOverall` 与 `digitAccuracy`；
3. 同时跑手写评测（现有 239 项单测 + 画板样本），确认手写没有回退；
4. 若微调有效，把"拍照"链路的默认模型切到新版本。
