# 导入图片识别：使用与验证范围

面向演示使用者与项目成员。网页版和小程序均新增用户主动选图、预览、再识别的输入方式。它复用现有账号、空间与模型，不是多数字OCR，也不保证任意照片准确率。

## 使用步骤

### 网页

1. 登录后进入“手写识别/画板”。
2. 切换到“导入图片”，选择电脑上的PNG/JPEG文件。
3. 查看预览，必要时更换或移除；此时尚未上传。
4. 点击“识别图片”，查看数字、置信度和耗时。若提示无法可靠识别，请更换清晰单数字图片或重新书写。
5. 切回“手写数字”可继续使用原画板；切换输入方式会清除上一输入的结果。

### 小程序

1. 登录后切到“导入图片”。
2. 点击“从相册选择”，仅选择一张原图，不使用相机。
3. 本地校验后显示预览，再点击“识别图片”上传。
4. 相册选择返回时会重新核验账号和空间；换账号/空间或离开页面后，旧选择不会带入新操作。

## 输入限制与数据处理

- 只接受PNG/JPEG，非空、≤5MiB、单边≤2048像素，总像素≤4,194,304。
- 建议白底黑字、单个0–9、清晰且适当留白。不支持多数字分割、照片场景OCR或相机入口。
- 不依赖扩展名判格式；前端做本地初检，Java/Python仍以实际字节、解码和尺寸做最终验证。
- 仅访问用户明确选择的文件/相册图片，不扫描相册；选择和预览不会自动上传，点击识别才上传。
- 原图不在业务系统长期保存、不用于训练；平台临时文件、日志和备份处理仍按已有隐私说明，不承诺临时文件即时删除。
- 不自动压缩/缩放逃避大小限制；提交原始已验证字节，PNG/JPEG使用现有同一识别协议。来源仍为WEB/MINIPROGRAM，不引入IMPORT权限类别。
- 通用拒识仍是实验性接受策略，可能拒绝部分合法数字或漏过乱画；高置信度不等于实际准确率，用户9误识别样例尚未复现。

## 本次验证结果（2026-11-05）

- 网页202项、小程序432项逻辑测试通过；合计634项。打包工具108项通过，三者合并742项，0失败/跳过，不重复累计。
- Java132项回归与打包通过；Python158项通过。后台PNG/JPEG/拒识合同保持不变，不重新训练模型。
- development和pilot网页构建通过；pilot使用明确本地测试的公开字段，不是实际发布配置。最终本机dist恢复development。
- Edge实际导入9项检查通过：空图片不可提交；PNG/JPEG本地预览后识别7；保存的image_digest与原文件SHA256一致；移除清结果；损坏/超尺寸/超字节本地拦截；导入实心块422且不退出；返回手写模式清预览。
- 前两次浏览器检查因测试驱动假设错误而失败：浏览器multipart调试数据未完整包含文件正文，改用后端实际接收摘要核对；错误提示位于role=alert而非只用于校验中的testid，修正测试定位。未跳过原字节、校验或识别检查，整条重跑通过。
- 小程序模拟测试覆盖相册回调先/后于onShow、验证失败、换图/卸载/账号origin/空间切换、取消和旧401/422。**没有完成微信真实相册选择、EXIF显示、wx.uploadFile或平台隐私授权验收**，这些仍需要开发者工具/设备复测。
- 小程序JPEG尺寸信息须在前64KiB内可解析；超长头部保守拒绝，不扩大无界读取。网页真实解码只是客户端初检，最终服务器校验仍权威。
- 发布工具真实源扫描checked，但未提供HTTPS/维护主体/联系/隐私版本/AppID时整体blocked为预期，未生成实际微信发布包、未上传或部署。
- 本轮临时服务验证结束已停止，代码和拒识前置改动保留本地，未提交/推送；AppID/private配置和历史证据未改。
