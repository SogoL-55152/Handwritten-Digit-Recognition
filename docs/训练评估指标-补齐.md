# 训练评估指标补齐（P/R/F1 · 三域混淆矩阵 · 错误样本回溯）

> 对应交接文档 P1-7：「评估指标补齐（P/R/F1、每类混淆矩阵、错误样本回溯）——训练记录页已有三域准确率，缺查准/查全」
> 完成日期：2026-11-25

---

## 1. 改动前

训练结束只产出两个数字集：

```json
"before": { "raw_mnist_1000": 0.114, "canvas_simulated_1000": 0.140, "photo_simulated_1000": 0.106 },
"after":  { "raw_mnist_1000": 0.820, "canvas_simulated_1000": 0.897, "photo_simulated_1000": 0.352 },
"detailed_canvas": { "perClass": [{ "label": 0, "correct": 87, "total": 100, "accuracy": 0.87 }, ...],
                     "confusion": [[...10×10...]],
                     "worst": [{ "label": 8, "accuracy": 0.55 }] }
```

问题：
1. **只有画板域**有混淆矩阵，原始 MNIST 与照片域只有一个小数；
2. 只有**每类准确率**，没有查准率/查全率/F1——「8 被判成 4」和「4 被判成 8」在准确率上看不出差别；
3. 判错的样本**无法回看**，不知道错在哪、错得多自信。

## 2. 改动后

### 2.1 指标结构（metrics.json / 任务详情接口）

```json
"detailed": {
  "raw_mnist":        { "...": "结构同下" },
  "canvas_simulated": {
    "domain": "canvas_simulated",
    "total": 1000, "correct": 821, "accuracy": 0.821,
    "perClass": [
      { "label": 3, "support": 107, "predicted": 97, "correct": 89,
        "accuracy": 0.8318, "precision": 0.9175, "recall": 0.8318, "f1": 0.8726 }
    ],
    "macro":    { "precision": 0.8273, "recall": 0.8146, "f1": 0.814, "classes": 10 },
    "weighted": { "f1": 0.8191 },
    "confusion": [[...10×10...]],
    "worst":  [ { "label": 8, "f1": 0.6197, "recall": 0.4944, "precision": 0.8302, "support": 89 } ],
    "errorCount": 179,
    "errors": [
      { "index": 290, "truth": 8, "predicted": 4, "confidence": 0.8766 }
    ],
    "errorSheet": "errors-canvas_simulated.png"
  },
  "photo_simulated": { "...": "同上" }
},
"detailed_canvas": { "...": "= detailed.canvas_simulated，兼容旧前端/旧记录" }
```

字段口径：

| 字段 | 含义 |
|---|---|
| `support` | 该数字在评估集里的**真实**样本数（行和） |
| `predicted` | 被判成该数字的样本数（列和） |
| `correct` | 对角线元素 |
| `precision` | `correct / predicted`（判成它的里面有多少是对的） |
| `recall` | `correct / support`（它有多少被找出来） |
| `f1` | `2PR/(P+R)`；`P+R=0` 时为 `0.0` |
| `macro` | 对**出现过**的类求平均（`support>0` 或 `predicted>0`），`classes` 是参与平均的类数 |
| `weighted.f1` | 按 `support` 加权的 F1 |
| `errors` | 判错的样本，**按置信度倒序**取前 20 条：模型越确定却判错，越可能是标签噪声或分布偏移 |
| `errorSheet` | 同目录下 `errors-<domain>.png` 联络表，便于人工回看 |

> **分母为 0 时返回 `null` 而不是 0**：某个类在评估集里压根没出现，说它"准确率 0%"是误导。前端显示为 `—`。

### 2.2 错误样本联络表

`weights/w4-train/<taskId>/<attempt>/errors-<domain>.png`：把前 20 个错误样本按 6 列拼成一张图（56×56/格），
方便直接打开看"错的是什么图"。实测生成的三张图（原始/画板/照片）各 6–7 KB，
`metrics.json` 从 ~10 KB 增至 ~32 KB，数据库 `metrics` 列（JSON）存 15.7 KB。

### 2.3 前端（训练记录 / 训练向导里的「每类准确率」区块）

`frontend/src/training/TrainingMatrix.vue` + `matrix.js`：

- 顶部出现 **评估域切换**：原始 MNIST / 画板模拟 / 照片模拟（旧记录只有一个域时自动隐藏）；
- 新增「查准 / 查全 / F1」表：每类 `样本 / 准确率 / P / R / F1`，表头右侧给宏平均与加权 F1；
- 新增「错误样本回溯」：`#索引 真实 X → 判成 Y（置信度 97.6%）`，并提示同目录的联络表文件名；
- 旧记录（只有 `detailed_canvas`、`total` 而非 `support`）依然能渲染——`matrix.js` 对两种结构都做了兼容。

## 4. 已知局限

1. **模拟域偏乐观**：canvas/photo 模拟集与训练同源（同一套生成器），指标只用于"域内回归"，
   不能当成真实画板/相册准确率——这一点在 `metrics.limitations` 里原本就有，未改动。
2. **错误样本只给索引与联络表**：接口不返回图片本身（避免把权重目录暴露成静态资源）；
   要逐张看请打开 `errorSheet` 指向的 PNG。
3. **`index` 的含义是"评估集内的序号"**，不是数据库样本 id；评估集由 seed+渲染随机数确定，
   同一 seed 下可复现。
4. **宏平均口径**：只在"出现过的类"上平均（与 sklearn 默认的 `labels=None` 基本一致），
   若将来评估集类别不均衡，需要在报告里同时看 `weighted.f1`。
