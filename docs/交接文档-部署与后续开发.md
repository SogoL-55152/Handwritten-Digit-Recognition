## 1. 项目是什么

手写数字识别系统，四端组成：

| 端 | 技术 | 作用 |
|---|---|---|
| 管理端前端 | Vue 3 + Vite | 数据集、导入、训练模型、训练记录、模型管理、公共资产、平台状态 |
| 后端 | Spring Boot 3.2 + Java 17 + JdbcTemplate + Flyway | 统一业务网关、权限、训练任务编排 |
| 模型服务 | Flask + PyTorch 2.5（CPU） | 在线识别、预处理、模型注册表、训练执行（Celery worker） |
| 小程序 | 微信小程序 | 画板识别、结果查看 |

中间件：MySQL 8.0、Redis 7、Celery（队列 `training`）。

## 4. 启动 / 停止

### 一键脚本（**建议接手后第一件事就是写**）

目前没有脚本，只能按下面顺序手动起。建议落成：

```
scripts/start-all.ps1   # 按顺序起：MySQL → Redis → 模型 → 后端 → worker → 前端
scripts/stop-all.ps1    # 反向顺序停
```

启动顺序不能乱：**MySQL、Redis 先起**，否则后端启动即失败。

### 手动启动（Windows PowerShell）

```powershell
# 1) Redis
Start-Process 'D:\Temp\hdr-w4-redis\bin\redis-server.exe' -ArgumentList '--port','16379','--bind','127.0.0.1'

# 2) MySQL
Start-Process 'D:\Temp\hdr-w2-mysql-runtime\mysql-8.0.40-winx64\bin\mysqld.exe' `
  -ArgumentList "--no-defaults","--basedir=D:\Temp\hdr-w2-mysql-runtime\mysql-8.0.40-winx64", `
  "--datadir=D:\Temp\hdr-w2-mysql-state-20261103\data","--bind-address=127.0.0.1","--port=13316", `
  "--mysqlx=OFF","--default-time-zone=+00:00","--console"

# 3) 模型服务（在仓库根目录）
Start-Process 'D:\Temp\hdr-w4-venv2\Scripts\python.exe' -ArgumentList '-I','model-service/serve.py'

# 4) 后端（在仓库根目录）
Start-Process 'D:\Temp\hdr-w1-jdk-runtime\jdk-17.0.2\bin\java.exe' `
  -ArgumentList '-jar','backend\target\hdr-backend-0.1.0-SNAPSHOT.jar'

# 5) Celery worker（工作目录必须是 model-service）
Start-Process 'D:\Temp\hdr-w4-venv2\Scripts\python.exe' `
  -ArgumentList '-m','celery','-A','celery_app:celery_app','worker','--pool=solo','-Q','training','--loglevel=INFO' `
  -WorkingDirectory .\model-service

# 6) 前端（开发模式）
Start-Process 'D:\Temp\hdr-w1-node-runtime\node-v22.23.4-win-x64\node.exe' `
  -ArgumentList 'node_modules/vite/bin/vite.js','--host','127.0.0.1','--port','5173','--strictPort' `
  -WorkingDirectory .\frontend
```

## 5. 关键环境变量

后端与模型服务/worker 必须用同一套值，**漏一个就会出问题**（历史上漏 `REDIS_HOST/REDIS_PORT` 导致日志接口空返回，漏 `HDR_IMPORT_ROOT` 导致 C 盘目录导不进去）。

| 变量 | 示例值 | 作用 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | `default` | 后端 profile |
| `HDR_PILOT_ENABLED` / `HDR_LEGACY_AUTH_ENABLED` / `HDR_LEGACY_BOOTSTRAP_ENABLED` | `false` | 关闭旧版登录与试点模式 |
| `MODEL_SERVICE_URL` | `http://127.0.0.1:5001` | 后端调模型服务 |
| `MODEL_REGISTRY_PATH` | `...\model-service\weights\registry.json` | 模型注册表 |
| `WEIGHTS_DIR` | `...\model-service\weights` | 权重目录 |
| `MODEL_INTERNAL_TOKEN` | `hdr-internal-dev` | 后端 ↔ 模型服务内部认证（三处必须一致） |
| `REDIS_URL` / `REDIS_HOST` / `REDIS_PORT` | `redis://127.0.0.1:16379/0` / `127.0.0.1` / `16379` | Redis 连接（**两个都要给**） |
| `HDR_COLLECTED_DIR` | `...\collected-samples` | 采集样本文件 |
| `HDR_RECOGNITION_DIR` | `...\recognition-images` | 识别图片存档 |
| `HDR_TRAINING_DATA_DIR` | `...\training-data` | 训练导出目录 |
| `TRAINING_CALLBACK_URL` | `http://127.0.0.1:8080` | worker 回调后端 |
| `HDR_IMPORT_ROOT` | `D:\;C:\` | 允许导入的根目录（分号分隔多个） |
| `HDR_IMPORT_PYTHON` | venv python | 导入时裁字脚本用的解释器 |
| `TRAINING_DATA_DIR` | `...\model-service\data\MNIST\raw` | 内置 MNIST 原始 IDX |
| `HDR_PREPROCESS_DESPECKLE` / `HDR_PREPROCESS_UPSCALE` | `1` / `1` | 预处理去斑、小目标放大（可设 0 对比） |

## 7. 数据库

- 迁移工具 Flyway，版本 **V1–V21**，启动时自动执行
- **不要修改历史迁移文件**；新增迁移用下一个版本号
- 关键表：
  - `t_collected_sample`（样本池；`source` = WEB/IMPORT，`source_dataset_id` 归属，`multi_digit` 巡检标记）
  - `t_v2_dataset` / `t_v2_dataset_version` / `t_v2_dataset_sample`
  - `t_import_batch`（导入批次，可回滚）
  - `t_v2_training_task` / `t_v2_training_metric` / `t_v2_model`
- 备份：

```powershell
mysqldump -h127.0.0.1 -P13316 -u root -p --databases hdr_w2_it_live > backup.sql
```

- 恢复：先停后端，`mysql < backup.sql`，再起后端（Flyway 会校验 schema history）

## 8. 训练链路（接手必读）

```
前端提交（秒回） → 后端写 QUEUED 入 Redis → worker 取任务
   → POST /internal/v2/training/{id}/prepare 取数据（导出/命中缓存）
   → 逐轮训练，每轮回调指标（前端轮询刷新）
   → 保存 checkpoint → 算 sha256 → 写 registry → 登记模型
   → 任务 SUCCEEDED
```

关键点：

| 点 | 说明 |
|---|---|
| 参数白名单 | 模型服务 `internal_v2.py` 的 `TRAINING_FIELDS` 必须与后端字段一致，否则 400「训练参数字段必须与约定一致」 |
| 按层训练 | `trainFrom` 四档 + `trainableLayers`；fc2 必须可训练（三层都校验） |
| 导出缓存 | `training-data/v<id>/.export.json`，样本数一致即复用 |
| 硬链接 | 同盘导出用 `Files.createLink`，几万张也是秒级；跨盘自动回退复制 |
| 训练产物 | `weights/w4-train/<taskId>/a<attempt>/checkpoint.pt` + `registry.json` |
| 激活 | 模型管理页「设为生效」；识别接口立即切换 |

## 10. 压测建议

| 场景 | 指标 | 注意 |
|---|---|---|
| 识别接口 | QPS、P95 延迟、错误率 | 需要真实图片；限流阈值在代码里 |
| 多位数识别 | 同上 | 切分耗时更高 |
| 训练并发 | 排队时间、单任务耗时 | worker `--pool=solo` **只能跑一个**；要并发需加 worker 数量 |
| 导入 | 1k/1万张耗时 | 大 zip 上传受网络影响 |
| 数据库 | 连接数、慢查询 | 关注 `t_collected_sample` 与版本样本查询 |

压测环境与开发环境**必须分开 Redis**，否则训练任务会被另一边 worker 取走。

## 11. 已知坑与排查

| 现象 | 原因 / 解决 |
|---|---|
| 前端 5173 打不开 | Vite 进程挂了；重启前端 |
| 后端起来但日志接口空、SSE 不推 | 漏了 `REDIS_HOST/REDIS_PORT`（`REDIS_URL` 不够） |
| C 盘目录导入报「必须位于允许的根目录下」 | `HDR_IMPORT_ROOT` 没配 `C:\`，设为 `D:\;C:\` |
| 训练提交 400「训练参数字段必须与约定一致」 | 模型服务 `TRAINING_FIELDS` 与新字段不同步 |
| 训练 400「该版本没有训练集样本」 | 版本 TRAIN 为 0；重新生成版本，样本少时验证/测试比例设 0 |
| 训练任务 attempt=2 | 历史问题：首次回调失败后按租约重投；现在正常应 attempt=1，若复现查 worker 的 `MODEL_INTERNAL_TOKEN` 与 `TRAINING_CALLBACK_URL` |
| 导入了多位数图被当单字 | 用「巡检多位数」标记后删除；试运行里也会抽样提示 |
| 9/7 这类细笔画被拒识（422） | 选择性识别：置信度 <0.90 或 margin <0.85 就拒识；改善拍摄（占画面 1/3、深色笔、均匀光）或用真实数据微调 |
| 后端打包失败 `repackage` | 后端进程占用 jar，先停后端 |
| `git push` 失败 | 网络到 GitHub 不稳；重试或配代理 |
| 前端改了不生效 | 硬刷新 `Ctrl+Shift+R`；确认访问的是 5173 而不是构建产物 |
